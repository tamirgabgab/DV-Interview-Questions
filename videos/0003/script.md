# 0003 — what does this code do: the video script

The storyboard of the video: the captions of every beat (Hebrew, a `> ` line per caption
line, a blank line between captions), in the order the video shows them. The captions are
exactly what the video shows; `videos/render.py` fails when scene.py's captions differ.

The example is the page's, `A = [3, 1, 4, 2]`: 16 comparisons, 5 swaps, an ascending sort. The code is the question itself (the page's Python `mystery`), so it is shown whole, not typed (the owner, 2026-10-31), and its lines are explained one by one. The page's box (the trace box, loop mode) is shown twice: alone, `i = 0` comparison by comparison and then "until the end of i" for `i = 1, 2, 3` (`BOXES['endi']`); and beside the code, where the run stops on every swap (`BOXES['all']`, the box's own copy of the code hidden). Then the invariant step by step, the cost, and the trap of the inner loop from `j = i + 1`.

## Chapter מה הקוד עושה – לולאה כפולה עם swap

> הנה הקוד של השאלה, ב-Python.
> ננסה להבין מה הוא עושה.

> הפונקציה mystery מקבלת רשימה A
> של מספרים שלמים, ומשנה אותה במקום.

> קודם n, מספר האיברים ב-A.

> הלולאה החיצונית : i עובר
> על כל האינדקסים, מ-0 עד n − 1.

> הלולאה הפנימית : גם j עובר על כולם,
> מ-0, ולא רק על אלה שאחרי i.

> אם A[i] קטן מ-A[j],
> מחליפים ביניהם.

> במבט ראשון זה נראה כמו מיון יורד :
> איבר קטן ב-i מתחלף עם איבר גדול ממנו.

> אבל לפני שעונים, מריצים דוגמה קטנה.
> השאלה מבקשת מערך בגודל 4.

> התיבה שבעמוד מריצה את הקוד
> על המערך של העמוד : 3, 1, 4, 2.

> השוואה 1 : i = 0 ו-j = 0.
> האם 3 < 3? לא, אין החלפה.

> השוואה 2 : j = 1.
> האם 3 < 1? לא.

> השוואה 3 : j = 2. האם 3 < 4? כן.
> מחליפים, ו-A הוא 4, 1, 3, 2.

> השוואה 4 : האם 4 < 2? לא.
> בסוף i = 0, המקסימום 4 יושב ב-A[0].

> הכפתור "עד סוף i" משלים את i = 1 :
> החלפה אחת, ב-j = 0, של 1 עם 4.

> סוף i = 2 : החלפה אחת, ב-j = 1.
> ה-3 נכנס לפני ה-4 : 1, 3, 4, 2.

> סוף i = 3 : שתי החלפות, ב-j = 1 וב-j = 2.
> המערך 1, 2, 3, 4.

> התשובה : הקוד ממיין בסדר עולה,
> מהקטן לגדול. לא יורד!

> נחזור לקוד ונריץ אותו על הדוגמה,
> לצד התיבה, ונעצור על כל החלפה.

> בהתחלה n = 4,
> ו-A הוא 3, 1, 4, 2.

> השוואה 1 : i = 0, j = 0.
> ‏3 < 3 לא מתקיים.

> השוואה 2 : 3 < 1. לא.

> השוואה 3 : 3 < 4. כן,
> וההחלפה מביאה את 4 ל-A[0].

> השוואה 4 : 4 < 2. לא. הלולאה הפנימית
> נגמרה, והמקסימום ב-A[0].

> ב-i = 1 כבר ההשוואה הראשונה מחליפה :
> ‏1 < 4, וה-1 עובר להתחלה.

> עכשיו A[1] הוא 4, המקסימום,
> ולכן בשאר ה-j של i = 1 אין החלפות.

> ב-i = 2 : 3 < 1 לא, אבל 3 < 4 כן.
> ה-3 נכנס לפני ה-4 : 1, 3, 4, 2.

> ב-j = 2 וב-j = 3, A[2] הוא 4,
> המקסימום, ואין החלפות.

> ב-i = 3 : 2 < 3, וה-2 מתחלף עם ה-3.
> המערך 1, 2, 4, 3.

> ב-j = 2 : 3 < 4, עוד החלפה,
> והמערך 1, 2, 3, 4.

> ההשוואה האחרונה, 4 < 4, לא מתקיימת.
> ‏16 השוואות, 5 החלפות, ומיון עולה.

> למה זה עובד תמיד? נסתכל על המערך
> בסוף כל איטרציה של i.

> הטענה : בסוף איטרציה i, החלק A[0..i]
> ממוין, ו-A[i] הוא המקסימום של כל המערך.

> שלב 1, i = 0 : כל איבר גדול יותר מתחלף
> עם A[0], ולכן בסוף A[0] הוא המקסימום.

> שלב 2, j < i : A[i] נכנס למקומו בחלק
> הממוין, כמו ב-insertion sort.

> הגדולים ממנו זזים מקום אחד ימינה,
> והמקסימום מגיע בדיוק ל-A[i].

> שלב 3, j ≥ i : A[i] הוא כבר המקסימום,
> ולכן התנאי לא מתקיים ואין החלפות.

> שלב 4 : אחרי i = n − 1, החלק הממוין
> הוא כל המערך. מיון עולה.

> הסיבוכיות : תמיד n² השוואות, גם
> כשהמערך כבר ממוין. זמן Θ(n²).

> אין יציאה מוקדמת, והמיון במקום :
> זיכרון נוסף O(1).

> על 4 איברים, 16 השוואות.
> על 1,000 איברים, מיליון השוואות.

> המלכודת : לנחש את הכיוון מהתנאי.
> הניחוש "יורד" נכון רק אם j מתחיל מ-i + 1.

> אז זה selection sort, והתוצאה 4, 3, 2, 1.
> אותו תנאי, כיוון הפוך.

> שם כל i מביא ל-A[i] את המקסימום
> של A[i..n − 1], ולכן הגדולים בהתחלה.
