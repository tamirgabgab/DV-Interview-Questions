## השאלה

תכננו מעגל שמקבל שעון `clk` ומוציא שעון `clk_out` בתדר **שליש** מתדר הכניסה, עם
**duty cycle של 50%** בדיוק: `clk_out` גבוה 1.5 מחזורים של `clk` ונמוך 1.5 מחזורים.

הסבירו למה מונה רגיל לא מספיק, שרטטו דיאגרמת תזמון, כתבו את המעגל ב-SystemVerilog,
וכתבו מודל Python שמדמה אותו חצי מחזור אחר חצי מחזור כדי לבדוק את התקופה ואת ה-duty.

??? interviewer "מה המראיין בודק"
    - **למה זה לא טריוויאלי:** עם מונה שמתקדם בעליית שעון בלבד כל האורכים הם מספר שלם
      של מחזורים, ו-1.5 אינו שלם. האם המועמד מזהה את זה מיד?
    - **שימוש בשתי השפות:** הרעיון של פלופ בירידת השעון, ומה המחיר שלו (אילוצי תזמון
      על חצי מחזור).
    - **גליצ'ים:** המוצא הוא שער OR של שני פלופים. האם המועמד בודק שהשער לא מייצר
      גליץ' במעברים?
    - **איפוס ומצב התחלתי:** מונה מודולו 3 מתוך 4 מצבים אפשריים: מה קורה אם הוא מתעורר
      במצב 3?
    - **אימות:** איך בודקים בטסטבנץ' שהתקופה היא 3 מחזורים וה-duty הוא 50%, ולא
      מסתפקים בהסתכלות על גל.

---

??? tip "רמז 1"
    פלופ שמתעדכן רק בעליית `clk` יכול לשנות את המוצא רק בעליות שעון, ולכן כל פולס שלו
    נמשך מספר **שלם** של מחזורים. מאיפה אפשר להשיג חצי מחזור?

??? tip "רמז 2"
    צרו שני אותות שכל אחד גבוה מחזור אחד מתוך שלושה, כשהשני מאוחר בחצי מחזור אחרי
    הראשון. מה נותן OR ביניהם?

??? success "פתרון"
    !!! answer "תשובה בקצרה"
        מונה מודולו 3 בעליית השעון; אות `a` רשום בעליית השעון, גבוה במחזור שבו המונה 0;
        אות `b` הוא `a` דגום **בירידת** השעון, כלומר אותו פולס מוזז בחצי מחזור;
        `clk_out = a | b` גבוה מעליית השעון של תחילת `a` עד ירידת השעון של סוף `b`: 1.5
        מחזורים מתוך 3.

    #### הרעיון { .sol-idea }

    מונה רגיל נותן פולס של מחזור אחד (33%) או שניים (67%), אף פעם לא 1.5. הדרך להוסיף
    "חצי" היא להשתמש גם בירידת השעון: לוקחים פולס של מחזור אחד, מעתיקים אותו עם פלופ
    שמתעדכן בירידת השעון, ומקבלים פולס זהה שמתחיל ונגמר חצי מחזור מאוחר יותר. OR של
    השניים הוא פולס שמתחיל עם הראשון ונגמר עם השני: מחזור ועוד חצי.

    #### השלבים { .sol-steps }

    <div class="steps" markdown>

    1. **מונה מודולו 3:** שני ביטים, סופר 0, 1, 2, 0, ...; מ-2 חוזרים ל-0 (ולא ל-3).
    2. **הפולס הבסיסי:** `a` נרשם בעליית השעון ושווה 1 בדיוק במחזור שבו המונה 0. הוא
       רשום (ולא `cnt == 0` צירופי) כדי שלא יהיו גליצ'ים מהמעבר `01` → `10` של המונה.
    3. **ההזזה:** `b <= a` בירידת השעון. `b` גבוה מהירידה שבאמצע מחזור 0 עד הירידה
       שבאמצע מחזור 1.
    4. **החיבור:** `clk_out = a | b` גבוה מעליית השעון של מחזור 0 עד ירידת השעון באמצע
       מחזור 1: 1.5 מחזורים. נמוך מאותה ירידה עד עליית השעון של מחזור 3: עוד 1.5.
    5. **אין גליץ':** המעברים של `a` ושל `b` אף פעם לא נופלים באותו רגע (אחד בעלייה,
       השני בירידה), ובכל מעבר של אחד מהם השני כבר בערך שמכסה אותו או שאין חפיפה
       שנדרשת: `a` יורד בעליית מחזור 1 כש-`b` כבר 1, ו-`b` יורד באמצע מחזור 1 כש-`a` כבר 0.
       לכן המוצא נקי.

    </div>

    #### הקוד { .sol-code }

    === "SystemVerilog"
        ```systemverilog title="module div3_50" linenums="1" hl_lines="11 12 16 19"
        module div3_50 (
          input  logic clk,
          input  logic rst_n,
          output logic clk_out
        );
          logic [1:0] cnt;
          logic a, b;

          always_ff @(posedge clk or negedge rst_n)
            if (!rst_n) begin cnt <= 2'd0; a <= 1'b0; end
            else begin
              cnt <= (cnt == 2'd2) ? 2'd0 : cnt + 2'd1;   // (1)!
              a   <= (cnt == 2'd2);                        // (2)!
            end

          always_ff @(negedge clk or negedge rst_n)
            if (!rst_n) b <= 1'b0;
            else        b <= a;                              // (3)!

          assign clk_out = a | b;                            // (4)!
        endmodule
        ```

        1. מונה מודולו 3. המצב `3` לא נגיש אחרי איפוס; בעיצוב מגן אפשר להחזיר ממנו ל-0
           (‏`cnt >= 2`), כדי שהפרעה לא תתקע את המונה.
        2. ‏`a` עולה בעליית השעון שבה המונה **עובר** ל-0, ולכן הוא גבוה בדיוק במחזור שבו
           `cnt == 0`, ישירות מפלופ, בלי לוגיקת פענוח במוצא.
        3. הפלופ היחיד בירידת השעון: `b` הוא `a` מוזז בחצי מחזור.
        4. המוצא הוא OR של שני פלופים. זה שער אחד במסלול השעון של הצרכנים, וצריך לשים
           לב לכך באילוצי התזמון.

    === "Python"
        ```python title="div3_50 (half-cycle model)" linenums="1" hl_lines="9 10 12 13"
        def div3_50(half_cycles: int) -> list[int]:
            """clk_out after each clock edge: edges 0, 2, 4, ... are rising, 1, 3, 5, ...
            falling. Models the two flops of the module: cnt and a on rising edges, b on
            falling edges."""
            cnt = a = b = 0
            out = []
            for edge in range(half_cycles):
                if edge % 2 == 0:                       # rising edge
                    a = 1 if cnt == 2 else 0            # (1)!
                    cnt = 0 if cnt == 2 else cnt + 1
                else:                                   # falling edge
                    b = a                               # (2)!
                out.append(a | b)                       # (3)!
            return out
        ```

        1. בעליית שעון: `a` מקבל את הערך לפי המונה **הישן**, ואז המונה מתקדם, בדיוק כמו
           שני המשפטים הלא-חוסמים במודול (שניהם קוראים את `cnt` מלפני השפה).
        2. בירידת שעון: `b` דוגם את `a`.
        3. אחרי כל שפה דוגמים את המוצא; רשימת הדגימות היא הגל בחצאי מחזורים.

    #### למה זה נכון { .sol-proof }

    **דיאגרמת תזמון.** שש מחזורי שעון, כלומר שתי תקופות של המוצא:

    ```wavedrom
    { signal: [
      { name: "clk",     wave: "p......" },
      { name: "cnt",     wave: "=======", data: ["0", "1", "2", "0", "1", "2", "0"] },
      { name: "a",       wave: "10.10.1" },
      { name: "b",       wave: "10.10.1", phase: -0.5 },
      { name: "clk_out", wave: "1..0..1..0..1.", period: 0.5 }
    ],
      head: { text: "clk_out = a | b: 1.5 cycles high, 1.5 cycles low" }
    }
    ```

    **ספירה מדויקת.** בחצאי מחזורים, מעליית השעון של מחזור 0: `a` גבוה בחצאים 0 ו-1,
    `b` גבוה בחצאים 1 ו-2, ולכן `clk_out` גבוה בחצאים 0, 1, 2 ונמוך בחצאים 3, 4, 5. שישה
    חצאים לתקופה, שלושה מהם גבוהים: תקופה של 3 מחזורי `clk` ו-duty של 50%. זה בדיוק מה
    שהמודל ב-Python מחזיר, והטסטבנץ' מודד את אותם ערכים על המודול עם `--timing`.

    **מצב התחלה.** אחרי איפוס `cnt = 0` ו-`a = 0`: במחזור הראשון המוצא נמוך, `a` עולה
    רק אחרי שהמונה השלים סיבוב (בעליית השעון השלישית). ההשהיה הזו לא משנה את התדר ואת
    ה-duty במצב היציב.

    #### סיבוכיות { .sol-cost }

    שלושה פלופים בעליית השעון (שניים למונה ואחד ל-`a`), פלופ אחד בירידת השעון ושער OR
    אחד. המחיר שלא רואים: הנתיב מ-`a` ל-`b` צריך להיסגר בתוך **חצי** מחזור, ושער ה-OR יושב
    במסלול שעון, ולכן כלי הסינתזה צריכים לדעת שזה שעון (clock definition על `clk_out`).

## נקודות חשובות ושאלות המשך

??? trap "מלכודת: לפענח את המוצא מהמונה"
    ‏`assign clk_out = (cnt == 0) | b` נראה חוסך פלופ, אבל `cnt == 0` הוא פענוח צירופי של
    שני ביטים שמשתנים יחד (‏`01` → `10`), ויכול לייצר גליץ' קצר. במסלול שעון גליץ' הוא
    שפה נוספת. המוצא של מחלק שעון יוצא תמיד ישירות מפלופים, או דרך שער שמובטח שאין בו
    מעברים חופפים.

??? trap "מלכודת: לשכוח את האיפוס של הפלופ בירידת השעון"
    ‏`b` הוא פלופ לכל דבר וצריך איפוס. בלי איפוס הוא יכול להתעורר ב-1, והמוצא יהיה גבוה
    עד הירידה הראשונה אחרי ש-`a` ירד. זה לא שובר את המצב היציב, אבל זה פולס ראשון באורך
    לא ידוע, וטסטבנץ' שסופר מהשפה הראשונה ייכשל.

??? followup "שאלות המשך"
    - **חלוקה ב-5 עם 50%:** אותו טריק: מונה מודולו 5, `a` גבוה שני מחזורים, `b` מוזז בחצי,
      והמוצא גבוה 2.5 מחזורים. באופן כללי לחלוקה ב-\( N \) אי-זוגי `a` גבוה
      \( (N-1)/2 \) מחזורים.
    - **בלי פלופ בירידת השעון:** אפשר לקבל 50% עם שעון כפול או עם PLL; בלי אלה, עם
      פלופים בעליית השעון בלבד, 50% בחלוקה אי-זוגית בלתי אפשרי. למה?
    - **מה הטסטבנץ' צריך למדוד:** לא רק את התקופה אלא גם את ה-duty, ועל הרבה תקופות,
      אחרי שהמעגל התייצב. איך מודדים זמן גבוה ב-SystemVerilog עם `$realtime`?
    - **מצב 3 של המונה:** אם המונה מתעורר ב-`2'd3` (בלי איפוס, או אחרי הפרעה), `cnt + 1`
      מחזיר אותו ל-0 וה-`a` יתעדכן לפי `cnt == 2` שהוא שקר: המעגל מתאושש לבד תוך מחזור.
      ומה קורה בעיצוב שמשווה `cnt == 3` כדי לחזור ל-0?
