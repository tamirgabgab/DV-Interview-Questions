## השאלה

על אי חיות **13 זיקיות אדומות**, **15 ירוקות** ו-**17 כחולות**. כששתי זיקיות בצבעים
שונים נפגשות, שתיהן מחליפות צבע ל**צבע השלישי** : אדומה וירוקה הופכות לשתי כחולות,
אדומה וכחולה לשתי ירוקות, וירוקה וכחולה לשתי אדומות. פגישה של שתי זיקיות באותו צבע לא
משנה כלום, ואף זיקית לא נולדת או מתה.

נסמן מצב בשלושה מספרים, \( (r, g, b) \) : כמה זיקיות אדומות, ירוקות וכחולות יש עכשיו.
פגישה של אדומה וירוקה מעבירה את \( (r, g, b) \) ל-\( (r - 1, g - 1, b + 2) \), וכך גם
שתי הפגישות האחרות.

??? interviewer "מה המראיין בודק"
    - **אינווריאנטה :** האם המועמד מחפש משהו שלא משתנה בפגישה, במקום לנסות פגישות ביד.
      הסכום לא משתנה, אבל הוא לא עוזר. מה שעוזר הוא השארית מודולו 3.
    - **שני כיווני ההוכחה :** "אי אפשר" מוכיחים באינווריאנטה, ו"אפשר" מוכיחים בבנייה. מועמד
      טוב לא מסתפק בתנאי הכרחי.
    - **חסם תחתון אמיתי :** פגישה יכולה גם **להגדיל** ספירה. האם הוא שם לב לזה כשהוא מוכיח
      שאי אפשר בפחות פגישות.
    - **מנוסחה לקוד :** פונקציה ב-\( O(1) \) לתשובה ובנייה מפורשת של הפגישות, ובדיקה מול
      חיפוש לרוחב על כל המצבים הקטנים.

### סעיף א – 13, 15 ו-17

האם ייתכן שיום אחד כל הזיקיות על האי יהיו באותו צבע? הוכיחו.

??? tip "רמז 1"
    מה פגישה עושה להפרש בין מספר האדומות למספר הירוקות? ולהפרשים האחרים?

??? tip "רמז 2"
    בפגישה, ספירה אחת גדלה ב-2 ושתיים קטנות ב-1. מודולו 3, להוסיף 2 ולהחסיר 1 זה אותו
    דבר.

??? success "פתרון סעיף א"
    !!! answer "תשובה בקצרה"
        לא. כל פגישה מוסיפה 2 לכל אחת משלוש הספירות **מודולו 3** (כי \( -1 \equiv 2 \)),
        ולכן ההפרשים ביניהן מודולו 3 לא משתנים לעולם. בהתחלה השאריות הן 1, 0 ו-2, שונות
        זו מזו. כשכולן באותו צבע, שתי ספירות הן 0 ושוות, וזה בלתי אפשרי.

    #### הרעיון { .sol-idea }

    **מה לא משתנה.** הסכום \( r + g + b = 45 \) נשמר, אבל כל מצב סופי, למשל
    \( (0, 0, 45) \), מקיים אותו, אז הוא לא פוסל כלום. צריך משהו עדין יותר.

    **מודולו 3.** פגישה של אדומה וירוקה משנה את הספירות ב-\( -1 \), ‏\( -1 \) ו-\( +2 \).
    מודולו 3, \( -1 \equiv +2 \), ולכן **כל** אחת משלוש הספירות גדלה ב-2. אותו דבר בשתי
    הפגישות האחרות. אם שלוש השאריות זזות יחד באותו צעד, ההפרשים ביניהן נשארים : השאריות
    שהיו שונות נשארות שונות, ושוות נשארות שוות.

    #### השלבים { .sol-steps }

    <div class="steps" markdown>

    1. **השאריות :** מחשבים את שלוש הספירות מודולו 3.
    2. **הכלל :** אם שלוש השאריות שונות זו מזו, הן נשארות שונות אחרי כל רצף של פגישות.
    3. **המסקנה :** במצב שבו כולן באותו צבע שתי ספירות הן 0, עם אותה שארית, ולכן לא
       מגיעים אליו.

    </div>

    #### למה זה נכון { .sol-proof }

    **שלוש פגישות, אחת מכל סוג.** השאריות זזות יחד, והן תמיד שלושת המספרים 0, 1 ו-2 בסדר
    כלשהו (בטבלה, \( \equiv \) הוא שוויון מודולו 3) :

    <!-- gen 2 -->

    | הפגישה | אדומות | ירוקות | כחולות |
    |---|:-:|:-:|:-:|
    | התחלה | ‏\( 13 \equiv 1 \) | ‏\( 15 \equiv 0 \) | ‏\( 17 \equiv 2 \) |
    | אדומה וירוקה | ‏\( 12 \equiv 0 \) | ‏\( 14 \equiv 2 \) | ‏\( 19 \equiv 1 \) |
    | אדומה וכחולה | ‏\( 11 \equiv 2 \) | ‏\( 16 \equiv 1 \) | ‏\( 18 \equiv 0 \) |
    | ירוקה וכחולה | ‏\( 13 \equiv 1 \) | ‏\( 15 \equiv 0 \) | ‏\( 17 \equiv 2 \) |

    <!-- /gen -->

    **בניסוח של הפרשים.** פגישה של אדומה וירוקה לא משנה את \( r - g \), ומשנה את
    \( g - b \) ואת \( r - b \) ב-\( -3 \). כך גם בשתי האחרות : כל הפרש משתנה ב-0 או
    ב-\( \pm 3 \), ולכן ההפרשים מודולו 3 קבועים לאורך כל ההיסטוריה של האי. בהתחלה אף הפרש
    לא מתחלק ב-3, ובמצב שבו כולן באותו צבע ההפרש בין שני הצבעים האחרים הוא 0.

### סעיף ב – כל r, g ו-b

עכשיו המספרים בהתחלה הם \( r \), \( g \) ו-\( b \), עם \( r + g + b > 0 \).

1. מתי אפשר להגיע למצב שבו כולן באותו צבע? הוכיחו את שני הכיוונים.
2. כתבו פונקציה שמחזירה רשימה של פגישות שמביאה את כולן לצבע נתון \( c \), כשזה אפשרי.

??? tip "רמז 1"
    הכיוון של "אי אפשר" כבר בסעיף א. לכיוון השני : נניח \( r \equiv g \pmod 3 \) ו-\( r \ge g \).
    מה קורה אם אדומות וירוקות נפגשות שוב ושוב?

??? tip "רמז 2"
    אחרי שהירוקות נגמרות נשארות \( r - g \) אדומות, מספר שמתחלק ב-3. איך שלוש פגישות
    יכולות להוריד שלוש אדומות ולהשאיר את הירוקות על 0?

??? success "פתרון סעיף ב"
    !!! answer "תשובה בקצרה"
        אפשר אם ורק אם **שתיים מהספירות שוות מודולו 3**. אז כולן יכולות להגיע לצבע
        השלישי, \( c \), חוץ ממקרה אחד : כשכל הזיקיות כבר בצבע אחד, כמו
        \( (3, 0, 0) \), אין שום פגישה. שם גם האדומות (3) והירוקות (0) שוות מודולו 3, אבל
        לכחול לא מגיעים, וכולן כבר באותו צבע, אדום. הבנייה : \( x \) ו-\( y \) הם שני הצבעים
        שאינם \( c \), עם \( s_x \ge s_y \) זיקיות. קודם \( s_y \) פגישות של \( x \) עם
        \( y \), ואחר כך שלשות של פגישות (\( x \) עם \( c \), ואז פעמיים \( x \) עם
        \( y \)), שכל אחת מורידה שלוש מ-\( x \). בסך הכול \( \max(s_x, s_y) \) פגישות.

    <!-- cost: פגישות \( \max(s_x, s_y) \) | זמן \( O(s_x + s_y) \) -->

    #### הרעיון { .sol-idea }

    **הכרחי.** כמו בסעיף א : ההפרשים מודולו 3 לא משתנים. אם בסוף כולן כחולות, אז
    \( r = g = 0 \) בסוף, ולכן \( r \equiv g \) כבר בהתחלה. כך גם לאדום ולירוק.

    **מספיק, בבנייה.** נניח \( r \equiv g \pmod 3 \) ו-\( r \ge g \), והמטרה כחול. פגישות
    של אדומה וירוקה מורידות את שתיהן באחד. אחרי \( g \) פגישות כאלה אין ירוקות, ונשארות
    \( r - g \) אדומות, מספר שמתחלק ב-3. עכשיו שלוש פגישות מורידות שלוש אדומות :
    אדומה וכחולה (נוצרות שתי ירוקות), ואז פעמיים אדומה וירוקה (הירוקות חוזרות ל-0). בכל
    שלישייה הכחולות גדלות ב-3, ולכן תמיד יש כחולה לפגישה הבאה.

    #### השלבים { .sol-steps }

    <div class="steps" markdown>

    1. **בדיקה :** שני הצבעים שאינם \( c \), נקרא להם \( x \) ו-\( y \), ו-\( s_x \),
       \( s_y \), \( s_c \) הם מספרי הזיקיות בשלושת הצבעים. אם \( s_x \not\equiv s_y \pmod 3 \),
       אין דרך.
    2. **סדר :** מחליפים בין \( x \) ל-\( y \) אם צריך, כך ש-\( s_x \ge s_y \).
    3. **שלב 1 :** כל עוד יש זיקיות בצבע \( y \), מפגישים \( x \) עם \( y \).
    4. **שלב 2 :** כל עוד יש זיקיות בצבע \( x \), מפגישים \( x \) עם \( c \), ואז פעמיים
       \( x \) עם \( y \).

    </div>

    #### הקוד { .sol-code }

    === "Python"
        ```python title="meeting_plan" linenums="1" hl_lines="8 14 17 19"
        def meeting_plan(counts, c):
            """Meetings that turn every chameleon to colour c (0 red, 1 green, 2 blue):
            [(i, j), ...], the pair of colours of each meeting. The two other counts must
            agree mod 3, and some other colour must be present."""
            s = list(counts)
            x, y = [k for k in range(3) if k != c]
            if s[x] < s[y]:
                x, y = y, x                                   # (1)!
            plan = []

            def meet(i, j):
                s[i] -= 1
                s[j] -= 1
                s[3 - i - j] += 2                             # (2)!
                plan.append((min(i, j), max(i, j)))

            while s[y] > 0:                                   # (3)!
                meet(x, y)
            while s[x] > 0:                                   # (4)!
                meet(x, c)
                meet(x, y)
                meet(x, y)
            return plan
        ```

        1. ‏\( x \) הוא הצבע עם יותר זיקיות מבין השניים, ו-\( y \) זה עם פחות. כך שלב 1 מרוקן
           את \( y \) לפני \( x \).
        2. שתי הזיקיות שנפגשו עוברות לצבע השלישי. שלושת הצבעים הם 0, 1 ו-2, ולכן השלישי
           הוא \( 3 - i - j \).
        3. שלב 1 : \( s_y \) פגישות. אחריו נשארות \( s_x - s_y \) זיקיות בצבע \( x \), מספר
           שמתחלק ב-3.
        4. שלב 2 : כל סיבוב מוריד שלוש מ-\( x \) ומשאיר את \( y \) על 0. יש בו תמיד זיקית
           בצבע \( c \) : אחרי שלב 1 יש לפחות \( 2 s_y \) כאלה, וכל סיבוב מוסיף שלוש.

    === "SystemVerilog"
        ```systemverilog title="function automatic int meeting_plan" linenums="1" hl_lines="8 11"
        // Meetings that turn every chameleon to colour c (0 red, 1 green, 2 blue). plan lists
        // them by the letters of the colours that meet, e.g. "RG RB RG RG"; returns how many.
        function automatic int meeting_plan(int cnt[3], int c, output string plan);
          string letter[3] = '{"R", "G", "B"};
          int s[3];
          int x = (c + 1) % 3, y = (c + 2) % 3, i, j, t, n = 0;
          s = cnt;
          if (s[x] < s[y]) begin t = x; x = y; y = t; end     // (1)!
          plan = "";
          while (s[x] > 0 || s[y] > 0) begin
            i = x; j = (s[y] > 0) ? y : c;                    // (2)!
            s[i]--; s[j]--; s[3 - i - j] += 2;
            if (plan != "") plan = {plan, " "};
            plan = {plan, (i < j) ? {letter[i], letter[j]} : {letter[j], letter[i]}};
            n++;
          end
          return n;
        endfunction
        ```

        1. כמו ב-Python : \( x \) הצבע עם יותר זיקיות מבין השניים שאינם \( c \), ו-\( y \) זה
           עם פחות.
        2. אותה בנייה בכלל אחד : \( x \) פוגשת את \( y \) כשיש כזו, ואחרת את \( c \). בשלב 1
           זה תמיד \( y \). בשלב 2 כל סיבוב מתחיל בלי \( y \), ולכן \( c \), ואחריו יש שתיים
           בצבע \( y \) לשתי הפגישות הבאות.

    #### למה זה נכון { .sol-proof }

    **הבנייה על דוגמה.** 7 אדומות, ירוקה אחת ו-3 כחולות : ‏\( 7 \equiv 1 \pmod 3 \), כמו
    הירוקה האחת, ולכן המטרה כחול. פגישה אחת של שלב 1, ואז שתי שלשות :

    <!-- gen 3 -->

    | פגישה | מי נפגשות | אדומות | ירוקות | כחולות |
    |:-:|---|:-:|:-:|:-:|
    | 0 | התחלה | 7 | 1 | 3 |
    | 1 | אדומה וירוקה | 6 | 0 | 5 |
    | 2 | אדומה וכחולה | 5 | 2 | 4 |
    | 3 | אדומה וירוקה | 4 | 1 | 6 |
    | 4 | אדומה וירוקה | 3 | 0 | 8 |
    | 5 | אדומה וכחולה | 2 | 2 | 7 |
    | 6 | אדומה וירוקה | 1 | 1 | 9 |
    | 7 | אדומה וירוקה | 0 | 0 | 11 |

    <!-- /gen -->

    **שלב 1 תמיד אפשרי.** כל פגישה בו מורידה באחד את הזיקיות בצבע \( x \) ואת אלה בצבע
    \( y \), ו-\( s_x \ge s_y \), ולכן \( x \) לא נגמר לפני \( y \). בסופו נשארות
    \( s_x - s_y \) בצבע \( x \), מספר ש-3 מחלק כי \( s_x \equiv s_y \).

    **שלב 2 תמיד אפשרי.** בתחילת כל סיבוב אין זיקיות בצבע \( y \), ומספר הזיקיות בצבע
    \( x \) מתחלק ב-3. הפגישה הראשונה צריכה זיקית בצבע \( c \) : אחרי שלב 1 יש
    \( s_c + 2 s_y \) כאלה (בספירות של ההתחלה). זה 0 רק אם \( s_c = s_y = 0 \), כלומר כל
    הזיקיות היו מלכתחילה בצבע \( x \), כמו \( (3, 0, 0) \) : אין שום פגישה אפשרית, וכולן
    כבר באותו צבע (רק לא \( c \)). בכל מקרה אחר יש לפחות אחת, וכל סיבוב מוסיף 3
    (\( -1 + 2 + 2 \)). אחרי הפגישה הראשונה יש שתיים בצבע \( y \), ושתי הפגישות הבאות
    מחזירות אותו ל-0 ומורידות עוד שתיים מ-\( x \).

    **הספירה.** \( s_y \) פגישות בשלב 1, ועוד \( s_x - s_y \) בשלב 2 (שלוש לכל שלוש), ובסך
    הכול \( s_x = \max(s_x, s_y) \).

### סעיף ג – הכי מעט פגישות

עכשיו נניח 13 אדומות, **16** ירוקות ו-17 כחולות.

1. לאיזה צבע אפשר להגיע, ובכמה פגישות לכל הפחות? הוכיחו שאי אפשר בפחות.
2. כתבו פונקציה שמקבלת \( (r, g, b) \) כלשהם ומחזירה את המספר המינימלי של פגישות עד
   שכולן באותו צבע, ואת הצבע. בדקו אותה מול חיפוש לרוחב (BFS) על כל המצבים הקטנים.

??? tip "רמז 1"
    ‏\( 13 \equiv 16 \equiv 1 \pmod 3 \), אז רק כחול אפשרי. הבנייה של סעיף ב לוקחת 16
    פגישות. האם אפשר פחות?

??? tip "רמז 2"
    ספרו כמה פגישות מכל סוג היו : \( p \) של אדומה וירוקה, \( q \) של אדומה וכחולה,
    \( t \) של ירוקה וכחולה. כתבו כמה אדומות נשארות בסוף. פגישה של ירוקה וכחולה
    **מוסיפה** שתי אדומות.

??? success "פתרון סעיף ג"
    !!! answer "תשובה בקצרה"
        כולן כחולות אחרי **16 פגישות**, ולא פחות. באופן כללי, כדי שכולן יגיעו לצבע \( c \)
        צריך בדיוק \( \max(s_x, s_y) \) פגישות, כש-\( x \) ו-\( y \) הם שני הצבעים האחרים,
        בתנאי ש-\( s_x \equiv s_y \pmod 3 \) (ושלא כל הזיקיות כבר בצבע אחר). כשכל שלוש
        הספירות שוות מודולו 3, הכי משתלם להגיע לצבע **הנפוץ ביותר**, ואז התשובה היא הספירה
        האמצעית.

    <!-- cost: זמן \( O(1) \) | בדיקה ב-BFS \( O(n^2) \) מצבים -->

    #### הרעיון { .sol-idea }

    **חסם עליון.** הבנייה של סעיף ב מגיעה לצבע \( c \) ב-\( \max(s_x, s_y) \) פגישות.

    **חסם תחתון, בספירה של הפגישות.** הטעות הנפוצה : "כל פגישה מורידה לכל היותר אדומה אחת,
    אז צריך לפחות \( r \) פגישות". זה לא נכון כמו שזה נשמע, כי פגישה של ירוקה וכחולה
    **מוסיפה** שתי אדומות. נכון יותר לספור. נניח שהיו \( p \) פגישות של אדומה וירוקה, \( q \)
    של אדומה וכחולה ו-\( t \) של ירוקה וכחולה, ובסוף כולן כחולות. בסוף אין אדומות,
    \( r - p - q + 2t = 0 \), ואין ירוקות, \( g - p + 2q - t = 0 \). לכן :

    \[
    \begin{aligned}
    r &= p + q - 2t \le p + q, \\
    g &= p - 2q + t \le p + t.
    \end{aligned}
    \]

    שני הצדדים הימניים קטנים או שווים ל-\( p + q + t \), מספר הפגישות. לכן צריך לפחות
    \( \max(r, g) \) פגישות, והבנייה מגיעה בדיוק לזה.

    **איזה צבע.** לכל צבע \( c \) שאפשר להגיע אליו, המחיר הוא הגדולה מבין שתי הספירות
    האחרות. כשרק זוג אחד שווה מודולו 3, הצבע נקבע. כשכל השלוש שוות, בוחרים את הצבע עם הכי
    הרבה זיקיות : אז שתי האחרות הן הקטנות, והמחיר הוא הספירה האמצעית.

    #### השלבים { .sol-steps }

    <div class="steps" markdown>

    1. **לכל צבע \( c \) :** \( x \) ו-\( y \) הם שני הצבעים האחרים. אם
       \( s_x \not\equiv s_y \pmod 3 \), הצבע הזה לא אפשרי.
    2. **מקרה הקצה :** אם \( s_c = 0 \) ואחת מ-\( s_x \), ‏\( s_y \) היא 0 (והשנייה לא), כל
       הזיקיות כבר בצבע אחר ואין שום פגישה. גם אז \( c \) לא אפשרי.
    3. **המחיר :** אחרת, \( \max(s_x, s_y) \) פגישות.
    4. **התשובה :** הצבע עם המחיר הקטן, ועל תיקו הצבע הראשון (אדום, ירוק, כחול).

    </div>

    #### הקוד { .sol-code }

    === "Python"
        ```python title="min_meetings" linenums="1" hl_lines="5 7 9"
        def meetings_to(counts, c):
            """The fewest meetings until every chameleon is of colour c (0 red, 1 green,
            2 blue), or None if that never happens."""
            sx, sy = (counts[k] for k in range(3) if k != c)
            if (sx - sy) % 3 != 0:
                return None                                   # (1)!
            if counts[c] == 0 and min(sx, sy) == 0 and max(sx, sy) > 0:
                return None                                   # (2)!
            return max(sx, sy)                                # (3)!


        def min_meetings(counts):
            """The fewest meetings until all share one colour: (meetings, colour), the first
            colour on a tie, or None if they never do."""
            best = None
            for c in range(3):
                m = meetings_to(counts, c)
                if m is not None and (best is None or m < best[0]):
                    best = (m, c)
            return best
        ```

        1. האינווריאנטה : בסוף שתי הספירות האחרות הן 0, ולכן הן חייבות להיות שוות מודולו 3
           כבר עכשיו.
        2. כל הזיקיות בצבע אחד שאינו \( c \) : אין זוג בצבעים שונים, ואין שום פגישה.
        3. החסם התחתון מהספירה של \( p \), \( q \) ו-\( t \), והבנייה של סעיף ב מגיעה אליו.

    === "SystemVerilog"
        ```systemverilog title="function automatic int min_meetings" linenums="1" hl_lines="5 6 7"
        // The fewest meetings until every chameleon is of colour c (0 red, 1 green, 2 blue),
        // or -1 if that never happens.
        function automatic int meetings_to(int cnt[3], int c);
          int sx = cnt[(c + 1) % 3], sy = cnt[(c + 2) % 3];
          if ((sx - sy) % 3 != 0) return -1;
          if (cnt[c] == 0 && (sx == 0 || sy == 0) && sx + sy > 0) return -1;
          return (sx > sy) ? sx : sy;
        endfunction

        // The fewest meetings until all share one colour, or -1; colour gets that colour,
        // the first one on a tie.
        function automatic int min_meetings(int cnt[3], output int colour);
          int best = -1, m;
          colour = -1;
          for (int c = 0; c < 3; c++) begin
            m = meetings_to(cnt, c);
            if (m >= 0 && (best < 0 || m < best)) begin best = m; colour = c; end
          end
          return best;
        endfunction
        ```

    #### סיבוכיות { .sol-cost }

    הנוסחה היא \( O(1) \), והבנייה \( O(\max(s_x, s_y)) \), פגישה בכל צעד. BFS עובר על כל

    למיליון זיקיות אלה כחצי טריליון מצבים, והנוסחה עונה מיד.
