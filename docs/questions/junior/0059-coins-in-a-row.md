## השאלה

על השולחן שורה של \( n \) מטבעות, \( n \) זוגי, ולכל מטבע ערך חיובי. שני שחקנים משחקים
בתורות, והראשון מתחיל. בכל תור השחקן לוקח מטבע **מאחד משני הקצוות** של השורה. כשהשורה
נגמרת, כל אחד סוכם את המטבעות שלקח, וכל אחד רוצה לקבל כמה שיותר.

- **סעיף א – לא להפסיד :** הוכיחו שהשחקן הראשון יכול תמיד לקבל לפחות חצי מהסכום, בלי
  לחשב כמעט כלום.
- **סעיף ב – החמדן :** "לקחת תמיד את הקצה הגדול" נשמע טבעי. הראו שהוא יכול להפסיד.
- **סעיף ג – המשחק הטוב ביותר :** כמה יקבל הראשון אם שניהם משחקים הכי טוב שאפשר? כתבו קוד.
- **סעיף ד – כמה הטריק מפסיד :** הטריק של סעיף א מבטיח חצי. כמה הוא יכול להשאיר על השולחן
  לעומת המשחק הטוב ביותר?
- **סעיף ה – ‏n אי-זוגי :** מה נשבר כשמספר המטבעות אי-זוגי?

??? interviewer "מה המראיין בודק"
    - **מבנה במקום חיפוש :** האם המועמד מחפש תכונה של השורה שהראשון יכול לכפות, ולא מנסה
      לנתח את כל המשחק.
    - **דוגמה נגדית :** האם הוא בודק את החמדן על שורה קטנה לפני שהוא מאמין לו.
    - **תכנון דינמי :** מצב = קטע של השורה, ערך = היתרון של מי שתורו. האם הוא מגיע ל-\( O(n^2) \)
      ולא לרקורסיה מעריכית.
    - **להבדיל בין "לא להפסיד" ל"לנצח בכמה שיותר" :** הטריק והתכנון הדינמי עונים על שתי
      שאלות שונות.

### סעיף א – הראשון לא מפסיד

??? tip "רמז 1"
    צבעו את המקומות בשורה לסירוגין : 1, 3, 5, ... בצבע אחד, ו-2, 4, 6, ... בצבע אחר. באיזה
    צבע הקצוות, כש-\( n \) זוגי?

??? tip "רמז 2"
    אם הראשון לוקח קצה בצבע מסוים, באיזה צבע שני הקצוות שנשארים לשני?

<div class="selfcheck" data-answer="6" data-show="6 : המקומות 1 ו-3 (1 + 5) מול 2 ו-4 (2 + 3)" data-hint="סכמו את המטבעות במקומות האי-זוגיים ואת אלה שבזוגיים, ובחרו את הגדול." markdown>
בשורה 1, 2, 5, 3, כמה מבטיח הטריק לשחקן הראשון?

??? success "פתרון סעיף א"
    !!! answer "תשובה בקצרה"
        צובעים את המקומות לסירוגין. הראשון יכול לקחת את **כל** המטבעות של צבע אחד : כש-\( n \)
        זוגי שני הקצוות בצבעים שונים, הוא לוקח את הקצה בצבע שלו, ושני הקצוות שנשארים לשני הם
        בצבע השני. לכן הוא בוחר את הצבע שסכומו גדול יותר, ומקבל לפחות חצי.

    **הראשון כופה צבע.** כשמספר המטבעות שנשארו זוגי, הקצה השמאלי והקצה הימני בצבעים
    שונים. הראשון לוקח את הקצה בצבע שלו. עכשיו נשארו מספר אי-זוגי של מטבעות, ושני הקצוות
    באותו צבע, הצבע של השני. מה שהשני ייקח, יחזיר לראשון שורה זוגית עם קצה אחד בכל צבע,
    וכן הלאה. בסוף הראשון לקח את כל המטבעות בצבע שבחר. בדוגמה הוא מתחיל דווקא מ-1, הקצה
    **הקטן**.

    #### הקוד { .sol-code }

    === "SystemVerilog"
        ```systemverilog title="function parity_move" linenums="1" hl_lines="4 5"
        // the first player's move on coins[i..j] (n even): 0 = the left end, 1 = the right end
        function automatic bit parity_move(int coins[], int i, int j);
          int odd_places = 0, even_places = 0;    // places 1, 3, ... are the indexes 0, 2, ...
          foreach (coins[k]) if (k % 2 == 0) odd_places += coins[k]; else even_places += coins[k];
          return (i % 2 == (odd_places >= even_places ? 0 : 1)) ? 1'b0 : 1'b1;   // (1)!
        endfunction
        ```

        1. הצבע נבחר לפי השורה כולה, פעם אחת. בכל תור של הראשון \( i \) ו-\( j \) בצבעים שונים, והוא לוקח את הקצה בצבע שלו.

    === "Python"
        ```python title="parity_move" linenums="1" hl_lines="3 4"
        def parity_move(coins: list[int], i: int, j: int) -> str:
            """The first player's move on coins[i..j] (n even): the end on the richer parity."""
            want = 0 if sum(coins[0::2]) >= sum(coins[1::2]) else 1     # (1)!
            return "L" if i % 2 == want else "R"
        ```

        1. ‏`coins[0::2]` הם המקומות 1, 3, 5, ... (האינדקסים 0, 2, 4, ...).

    #### למה זה נכון { .sol-proof }

    **שמורה :** בתחילת כל תור של הראשון נשארו מספר זוגי של מטבעות, \( i..j \), ולכן \( i \)
    ו-\( j \) בזוגיות שונה. הוא לוקח את הקצה שהזוגיות שלו היא הצבע שבחר. נשאר קטע באורך
    אי-זוגי ששני קצותיו באותה זוגיות, הצבע השני, ולכן השני לוקח מטבע מהצבע השני בכל מקרה.
    אחרי תורו השמורה חוזרת. בסוף הראשון לקח את כל הצבע שלו, שסכומו לפחות חצי.

??? tip "רמז 1"
    נסו שורות של ארבעה מטבעות. מתי הקצה הגדול פותח לשני מטבע גדול עוד יותר?

### סעיף ג – המשחק הטוב ביותר

??? tip "רמז 1"
    בכל רגע נשאר **קטע רציף** של השורה. כמה קטעים כאלה יש?

??? tip "רמז 2"
    הגדירו \( d[i][j] \) : בכמה מי שתורו יוביל על השני בקטע \( i..j \), אם שניהם משחקים הכי
    טוב. אם הוא לוקח את \( c_i \), היריב הופך להיות "מי שתורו" בקטע \( i+1..j \).

<div class="selfcheck" data-answer="19" data-show="19 מתוך 22" data-hint="הראשון לוקח את ה-9 שבקצה. איזה מטבע השני יכול לקחת בלי לחשוף את ה-9 השני?" markdown>
בשורה 1, 1, 9, 1, 1, 9, כמה יקבל הראשון אם שניהם משחקים הכי טוב?
</div>

??? success "פתרון סעיף ג"
    !!! answer "תשובה בקצרה"
        ‏\( d[i][j] = \max(c_i - d[i+1][j],\; c_j - d[i][j-1]) \), ו-\( d[i][i] = c_i \) : מי שתורו
        לוקח קצה, ואז היריב מוביל ב-\( d \) של מה שנשאר. ממלאים לפי אורך הקטע, ‏\( O(n^2) \)
        זמן וזיכרון, והראשון מקבל \( (\text{sum} + d[0][n-1]) / 2 \).

    <!-- cost: זמן \( O(n^2) \) | זיכרון \( O(n^2) \) -->

    #### הרעיון { .sol-idea }

    **המצב הוא קטע.** כל מהלך מוריד קצה, ולכן מה שנשאר הוא תמיד \( c_i..c_j \). יש רק
    \( n(n+1)/2 \) קטעים, ולכל אחד מספיק לדעת מספר אחד : **היתרון** של מי שתורו, כמה הוא
    יאסוף יותר מהיריב משם והלאה. אם הוא לוקח את \( c_i \), תורו של היריב בקטע \( i+1..j \),
    והיריב יוביל שם ב-\( d[i+1][j] \). לכן היתרון של לקיחת \( c_i \) הוא \( c_i - d[i+1][j] \).

    בשורה 1, 2, 5, 3 (שורה \( i \), עמודה \( j \), במקומות מ-1) :

    <!-- gen 3 -->

    | ‏i \\ j | ‏1 (1) | ‏2 (2) | ‏3 (5) | ‏4 (3) |
    |:-:|:-:|:-:|:-:|:-:|
    | ‏1 (1) | ‏1 | ‏1 | ‏4 | ‏1 |
    | ‏2 (2) |  | ‏2 | ‏3 | ‏0 |
    | ‏3 (5) |  |  | ‏5 | ‏2 |
    | ‏4 (3) |  |  |  | ‏3 |

    <!-- /gen -->

    ‏\( d[1][4] = 1 \) : הראשון מוביל באחד, כלומר \( (11 + 1)/2 = 6 \) מול 5.

    #### השלבים { .sol-steps }

    <div class="steps" markdown>

    1. **קטע של מטבע אחד :** ‏\( d[i][i] = c_i \).
    2. **לפי אורך :** לכל קטע \( i..j \), בוחרים בין \( c_i - d[i+1][j] \) ל-\( c_j - d[i][j-1] \),
       ושני הקטעים הקצרים כבר חושבו.
    3. **התשובה :** הראשון אוסף \( (\text{sum} + d[0][n-1]) / 2 \), והשני את השאר.
    4. **המהלך :** בכל קטע, הצד שנתן את המקסימום.

    </div>

    #### הקוד { .sol-code }

    === "SystemVerilog"
        ```systemverilog title="function best_total" linenums="1" hl_lines="11 12 13 15"
        // the most the first player collects when both play their best; d[i * n + j] is the
        // lead of the player to move on coins i..j
        function automatic int best_total(int coins[]);
          int n = coins.size(), total = 0, j, take_l, take_r;
          int d[];
          d = new[n * n];
          foreach (coins[i]) begin d[i * n + i] = coins[i]; total += coins[i]; end
          for (int len = 2; len <= n; len++)
            for (int i = 0; i + len - 1 < n; i++) begin
              j = i + len - 1;
              take_l = coins[i] - d[(i + 1) * n + j];   // (1)!
              take_r = coins[j] - d[i * n + j - 1];
              d[i * n + j] = (take_l > take_r) ? take_l : take_r;
            end
          return (total + d[n - 1]) / 2;                 // (2)!
        endfunction
        ```

        1. לוקח את \( c_i \), והיריב מוביל ב-\( d \) של הקטע שנשאר.
        2. ‏`d[n - 1]` הוא \( d[0][n-1] \). ‏\( \text{mine} - \text{other} = d \) ו-\( \text{mine} + \text{other} = \text{sum} \).

    === "Python"
        ```python title="best_total" linenums="1" hl_lines="10 11"
        def best_total(coins: list[int]) -> int:
            """The most the first player collects when both play their best (any n)."""
            n = len(coins)
            d = [[0] * n for _ in range(n)]          # d[i][j]: the mover's lead on coins i..j
            for i in range(n):
                d[i][i] = coins[i]
            for length in range(2, n + 1):
                for i in range(n - length + 1):
                    j = i + length - 1
                    d[i][j] = max(coins[i] - d[i + 1][j], coins[j] - d[i][j - 1])   # (1)!
            return (sum(coins) + d[0][n - 1]) // 2
        ```

        1. כל קטע תלוי רק בשני קטעים קצרים ממנו באחד, ולכן מספיק למלא לפי אורך.

    #### למה זה נכון { .sol-proof }

    באינדוקציה על אורך הקטע. אם מי שתורו לוקח את \( c_i \), מכאן והלאה היריב הוא "מי שתורו"
    בקטע \( i+1..j \), ולפי ההנחה הוא מוביל שם ב-\( d[i+1][j] \) בדיוק, כשהוא משחק הכי טוב
    והשחקן הראשון משחק הכי טוב נגדו. היתרון הכולל הוא \( c_i - d[i+1][j] \). אותו דבר עם \( c_j \),
    ומי שתורו בוחר את הטוב מהשניים.

    **נסו בעצמכם.** משחקים נגד המחשב, או בוחרים אסטרטגיה לכל שחקן ומריצים מהלך אחרי מהלך.
    הטבלה מתחת מראה את \( d \) של כל הקטעים, את הקטע של הרגע ואת המהלך שהיא ממליצה עליו :

### סעיף ד – כמה הטריק מפסיד

??? tip "רמז 1"
    הטריק לוקח צבע שלם. מה אם שני הצבעים שווים, אבל אפשר לקחת כמעט את כל המטבעות הגדולים?

??? success "פתרון סעיף ד"
    !!! answer "תשובה בקצרה"
        הרבה. בשורה 1, 1, 9, 1, 1, 9 שני הצבעים שווים 11, והטריק מקבל 11 מתוך 22, אבל המשחק
        הטוב ביותר מקבל 19. באופן כללי הטריק מבטיח רק חצי, והמשחק הטוב ביותר יכול להגיע כמעט
        לכל הסכום, כך שההפרש יכול להתקרב לחצי מהסכום.

    #### הרעיון { .sol-idea }

    הטריק מתחייב לצבע אחד מראש. בשורה 1, 1, 9, 1, 1, 9 ה-9 אחד במקום 3 (אי-זוגי) והשני במקום
    6 (זוגי), ולכן כל צבע מקבל רק אחד מהם. המשחק הטוב ביותר לוקח את ה-9 שבקצה, ואחר כך נשאר
    \( 1, 1, 9, 1, 1 \) : השני חייב לקחת 1, והראשון שומר על ה-9 השני עד שהשני נאלץ לחשוף אותו :

    <!-- gen 4 -->

    | המהלך | זוגיות מול אופטימלי | אופטימלי מול אופטימלי |
    |:-:|:-:|:-:|
    | ‏1 | הראשון : שמאל, ‏1 | הראשון : ימין, ‏9 |
    | ‏2 | השני : שמאל, ‏1 | השני : שמאל, ‏1 |
    | ‏3 | הראשון : שמאל, ‏9 | הראשון : ימין, ‏1 |
    | ‏4 | השני : ימין, ‏9 | השני : שמאל, ‏1 |
    | ‏5 | הראשון : ימין, ‏1 | הראשון : שמאל, ‏9 |
    | ‏6 | השני : שמאל, ‏1 | השני : שמאל, ‏1 |
    | **סך הכול** | **‏11 מול 11** | **‏19 מול 3** |

    <!-- /gen -->

    #### למה זה נכון { .sol-proof }

    **חצי מובטח, לא יותר :** הטריק מקבל בדיוק את סכום הצבע שבחר, \( \max(\text{odd}, \text{even}) \),
    וכשהצבעים שווים זה בדיוק חצי.

    **ההפרש יכול להתקרב לחצי :** בשורה \( \varepsilon, \varepsilon, 1, \varepsilon, \varepsilon, 1 \)
    הצבעים שווים, ‏\( 1 + 2\varepsilon \) כל אחד, אבל המשחק הטוב ביותר לוקח את שני ה-1 ועוד
    \( \varepsilon \). כש-\( \varepsilon \) קטן, הוא לוקח כמעט את הכול, והטריק רק חצי.

### סעיף ה – מספר אי-זוגי של מטבעות

??? tip "רמז 1"
    כש-\( n \) אי-זוגי, באיזה צבע שני הקצוות בתור הראשון?

<div class="selfcheck" data-answer="2" data-show="2 מתוך 7" data-hint="כל קצה שהראשון לוקח, השני לוקח את ה-5." markdown>
בשורה 1, 5, 1, כמה יקבל הראשון אם שניהם משחקים הכי טוב?
</div>

??? success "פתרון סעיף ה"
    !!! answer "תשובה בקצרה"
        הטריק נשבר : כש-\( n \) אי-זוגי שני הקצוות באותו צבע, והראשון לא יכול לבחור צבע. אחרי
        המהלך הראשון השני עומד מול שורה זוגית, ועכשיו **הוא** יכול להשתמש בטריק. בשורה 1, 5, 1
        הראשון מקבל 2 מתוך 7, לא משנה מה יעשה. התכנון הדינמי של סעיף ג עובד לכל \( n \).

    <!-- cost: הטריק \( O(n) \) | המשחק הטוב ביותר \( O(n^2) \) -->

    #### הרעיון { .sol-idea }

    המספר הזוגי היה מה שנתן לראשון את השליטה בצבע. במספר אי-זוגי התפקידים מתהפכים : הראשון
    לוקח מטבע אחד, והשני מקבל שורה זוגית ואת כל הכוח של סעיף א עליה. הראשון עדיין לוקח
    מטבע אחד יותר, ולכן לפעמים הוא מנצח, אבל אין לו הבטחה.

    #### למה זה נכון { .sol-proof }

    בשורה 1, 5, 1 הראשון לוקח 1 (שני הקצוות 1). השני רואה 5 ו-1 ולוקח 5, והראשון לוקח את ה-1
    האחרון : ‏2 מול 5. ‏`best_total([1, 5, 1])` נותן 2.

    #### סיבוכיות { .sol-cost }

    - **הטריק :** ‏\( O(n) \) פעם אחת לבחור צבע, ו-\( O(1) \) לכל מהלך.
    - **המשחק הטוב ביותר :** ‏\( O(n^2) \) זמן וזיכרון לטבלה. אם צריך רק את הערך, מספיקה שורה אחת
      של הטבלה בכל פעם, ‏\( O(n) \) זיכרון.

## נקודות חשובות ושאלות המשך

??? trap "מלכודת : לקחת תמיד את הגדול"
    החמדן מסתכל צעד אחד קדימה. סעיף ב מראה שהוא מפסיד כבר בארבעה מטבעות, והטריק של סעיף א
    מתחיל דווקא בקצה הקטן.

??? trap "מלכודת : 'הטריק הוא המשחק הטוב ביותר'"
    הטריק מבטיח לא להפסיד, אבל הוא לא האופטימום. בסעיף ד הוא משאיר 8 מתוך 22 על השולחן.

??? trap "מלכודת : רקורסיה בלי טבלה"
    ‏\( f(i, j) \) קורא ל-\( f(i+1, j) \) ול-\( f(i, j-1) \), ושניהם קוראים ל-\( f(i+1, j-1) \). בלי
    לשמור תוצאות, מספר הקריאות גדל כמו \( 2^n \).

??? followup "שאלות המשך"
    - **עד \( k \) מטבעות בתור :** מותר לקחת 1 עד \( k \) מטבעות מאותו קצה. מה משתנה בטבלה?

        ??? fu-answer "תשובה"
            אותו מצב, קטע \( i..j \), אבל המקסימום הוא על \( 2k \) מהלכים : ‏\( \sum_{t<m} c_{i+t} - d[i+m][j] \)
            או מהקצה השני, לכל \( m \le k \). עם סכומים מצטברים כל מהלך הוא \( O(1) \), כלומר \( O(n^2 k) \).

    - **רק הערך, בזיכרון קטן :** איך מחשבים את \( d[0][n-1] \) ב-\( O(n) \) זיכרון?

        ??? fu-answer "תשובה"
            ממלאים לפי אורך, וכל אורך תלוי רק באורך הקודם : מערך אחד של \( n \) תאים, שבו \( d[i] \)
            של אורך \( L \) מחליף את \( d[i] \) של אורך \( L - 1 \).

    - **שלושה שחקנים :** האם הטריק של הצבעים עובד?

        ??? fu-answer "תשובה"
            לא ישירות. במשחק של שלושה אין "היתרון שלי מול היריב" אחד, והמצב צריך את הסכום של כל
            שחקן. התכנון הדינמי עדיין עובד, עם וקטור של שלושה ערכים לכל קטע.
