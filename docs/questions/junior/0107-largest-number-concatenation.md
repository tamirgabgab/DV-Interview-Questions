## השאלה

נתונה רשימה של מספרים שלמים אי-שליליים. כותבים את כולם בשורה, זה אחרי זה ובלי רווחים, בסדר
שבוחרים. באיזה סדר מתקבל המספר הגדול ביותר? מחזירים אותו כמחרוזת, כי הוא יכול להיות ארוך
מכל טיפוס של מספר שלם.

**הדוגמה :** <span dir="ltr">[3, 30, 34, 5, 9]</span>. הסדר <span dir="ltr">9 ‖ 5 ‖ 34 ‖ 3 ‖ 30</span>
נותן 9534330, וזה הגדול ביותר. כאן ובהמשך ‖ הוא שרשור : <span dir="ltr">3 ‖ 30 = 330</span>.

**ההקשר באימות :** מזהה או מפתח שבונים משרשור של שדות עשרוניים, ומודל ייחוס שצריך לבחור את
הסדר שלהם. מודל כזה משווה או מחרוזות או ערכים, ובשאלה הזו שתי ההשוואות הישירות טועות.

- **סעיף א – כלל ההשוואה :** למה מיון של המספרים, או של המחרוזות, מהגדול לקטן לא עובד? מצאו כלל
  שמחליט מי משני מספרים בא קודם, וכתבו את הפתרון.
- **סעיף ב – למה זה נכון :** הוכיחו שהכלל הוא סדר אמיתי, כלומר טרנזיטיבי, ושמיון לפיו נותן את
  הגדול ביותר מכל הסדרים.
- **סעיף ג – הקטן ביותר :** עכשיו מחפשים את המספר הקטן ביותר, והוא לא יכול להתחיל ב-0 (אלא אם
  הוא 0). מה משתנה?

??? interviewer "מה המראיין בודק"
    - **זוג לפני רשימה :** האם המועמד בודק מה קורה לשני מספרים שכנים, במקום לנחש סדר לכל הרשימה.
    - **מיון עם כלל משלך :** האם הוא יודע להעביר לשפה כלל השוואה, ומה כלל כזה חייב לקיים כדי
      שהמיון יעבוד.
    - **הוכחה :** למה הכלל טרנזיטיבי, ולמה מיון לפי כלל מקומי נותן את המקסימום של כל הסדרים.
    - **מקרי קצה :** אפסים, תוצאה ארוכה מכל טיפוס מספרי, ושני מספרים ששני הסדרים שלהם שווים.
    - **שינוי קטן בדרישה :** האם הוא רואה שהקטן ביותר הוא לא המראה של הגדול ביותר.

### סעיף א – כלל ההשוואה

??? tip "רמז 1"
    קחו רק שני מספרים, 3 ו-30. יש להם שני סדרים בלבד. מה בדיוק צריך להשוות כדי לבחור ביניהם?

??? tip "רמז 2"
    כששני מספרים יושבים זה ליד זה בתוך הרשימה, מה משתנה במספר כולו כשמחליפים אותם, ומה נשאר כמו
    שהוא?

??? success "פתרון סעיף א"
    !!! answer "תשובה בקצרה"
        מיון של המספרים מהגדול לקטן שם את 34 ואת 30 לפני 9, ומיון של המחרוזות שם את "30" לפני
        "3", אבל <span dir="ltr">3 ‖ 30 = 330</span> גדול מ-<span dir="ltr">30 ‖ 3 = 303</span>.
        הכלל הנכון : \( a \) לפני \( b \) כש-\( a \Vert b > b \Vert a \), השוואה של שתי מחרוזות
        באותו אורך. ממיינים לפיו, משרשרים, ואם התוצאה מתחילה ב-0 מחזירים "0". הזמן
        \( O(n \log n \cdot L) \), כש-\( L \) האורך של המספר הארוך.

    <!-- cost: זמן \( O(n \log n \cdot L) \) | זיכרון \( O(n L) \) -->

    #### הרעיון { .sol-idea }

    **שני המיונים הישירים.** מספר עם יותר ספרות גדול יותר, אבל כשמשרשרים, מה שקובע הוא הספרה
    הראשונה ולא האורך. לכן מיון לפי ערך נכשל מיד : 34 ו-30 באים לפני 9. מיון של מחרוזות כבר
    מסתכל על הספרה הראשונה, אבל כשמחרוזת אחת היא תחילת השנייה, "3" ו-"30", הוא שם את הארוכה
    קודם, ולא תמיד זה נכון :

    <!-- gen 0 -->

    | המיון | הסדר | השרשור | התוצאה |
    |---|:-:|:-:|:-:|
    | מיון של המספרים, מהגדול לקטן | ‏<span dir="ltr">34 ‖ 30 ‖ 9 ‖ 5 ‖ 3</span> | ‏<span dir="ltr"><b>3</b>430953</span> | קטן יותר |
    | מיון של המחרוזות, מהגדולה לקטנה | ‏<span dir="ltr">9 ‖ 5 ‖ 34 ‖ 30 ‖ 3</span> | ‏<span dir="ltr">95343<b>0</b>3</span> | קטן יותר |
    | ‏\( a \Vert b \) מול \( b \Vert a \) | ‏<span dir="ltr">9 ‖ 5 ‖ 34 ‖ 3 ‖ 30</span> | ‏<span dir="ltr">9534330</span> | הגדול ביותר |

    <!-- /gen -->

    **הכלל.** נניח ש-\( a \) ו-\( b \) יושבים זה ליד זה. אם מחליפים ביניהם, כל מה שלפניהם וכל מה
    שאחריהם נשאר במקום, והאורך הכולל לא משתנה. לכן משווים רק את \( a \Vert b \) מול \( b \Vert a \) :
    שתי מחרוזות של ספרות באותו אורך, ולכן השוואה של מחרוזות היא בדיוק השוואה של המספרים. \( a \)
    בא קודם כש-\( a \Vert b > b \Vert a \).

    #### השלבים { .sol-steps }

    <div class="steps" markdown>

    1. **מחרוזות :** כל מספר הופך למחרוזת של הספרות שלו.
    2. **מיון :** ממיינים בכלל ההשוואה, \( a \) לפני \( b \) כש-\( a \Vert b > b \Vert a \).
    3. **שרשור :** מחברים את המחרוזות לפי הסדר.
    4. **אפסים :** אם התוצאה מתחילה ב-0, כל המספרים הם 0, ומחזירים "0".

    </div>

    #### הקוד { .sol-code }

    === "Python"
        ```python title="largest_number" linenums="1" hl_lines="6 15"
        from functools import cmp_to_key


        def concat_order(a: str, b: str) -> int:
            """In the largest number: -1 if a goes first, 1 if b does, 0 if a + b == b + a."""
            if a + b > b + a:                          # (1)!
                return -1
            if a + b < b + a:
                return 1
            return 0


        def largest_number(nums: list[int]) -> str:
            """The largest number made by concatenating all of nums, as a string."""
            s = sorted((str(x) for x in nums), key=cmp_to_key(concat_order))   # (2)!
            out = "".join(s)
            return "0" if out[0] == "0" else out       # (3)!
        ```

        1. ‏`a + b` כאן הוא שרשור של מחרוזות, ושתי המחרוזות באותו אורך : ההשוואה שלהן לפי סדר
           מילוני היא ההשוואה של המספרים.
        2. ‏`cmp_to_key` הופך פונקציית השוואה עם שלוש תשובות למפתח של מיון. הפונקציה חייבת
           להחזיר מספר שלילי, 0 או חיובי, ולא `True` / `False` (ראו המלכודת).
        3. אחרי המיון המספר הראשון הוא הגדול ביותר בכלל, ולכן אם הוא 0, כולם 0.

    === "SystemVerilog"
        ```systemverilog title="function largest_number" linenums="1" hl_lines="3 13 27"
        // a goes before b in the largest number: a + b is larger than b + a
        function automatic bit goes_first(string a, string b);
          return {a, b} > {b, a};                            // (1)!
        endfunction

        // insertion sort of the strings by goes_first: descending for the largest, ascending otherwise
        function automatic void sort_concat(ref string s[$], input bit largest);
          string key;
          int j;
          for (int i = 1; i < s.size(); i++) begin
            key = s[i];
            j = i - 1;
            while (j >= 0 && (largest ? goes_first(key, s[j]) : goes_first(s[j], key))) begin   // (2)!
              s[j + 1] = s[j];
              j--;
            end
            s[j + 1] = key;
          end
        endfunction

        // the largest number made by concatenating all of nums, as a string
        function automatic string largest_number(int nums[]);
          string s[$], out = "";
          foreach (nums[i]) s.push_back($sformatf("%0d", nums[i]));
          sort_concat(s, 1);
          foreach (s[i]) out = {out, s[i]};
          return out[0] == "0" ? "0" : out;
        endfunction
        ```

        1. ‏`{a, b}` של שני `string` הוא שרשור, ו-`>` משווה מחרוזות לפי סדר מילוני.
        2. ‏`sort()` של תור ב-SystemVerilog מקבל מפתח (`with`), לא פונקציית השוואה, ולכן כאן מיון
           הכנסה. ‏`&&` מקצר : כש-`j` הוא <span dir="ltr">−1</span> לא קוראים את `s[j]`.

    #### למה זה נכון { .sol-proof }

    הכלל מקומי : הוא אומר רק שבתשובה אין שני שכנים שהחלפה שלהם מגדילה את המספר. בתשובה של הדוגמה
    כל זוג שכנים עומד בו :

    <!-- gen 1 -->

    | הזוג | ‏\( a \Vert b \) | ‏\( b \Vert a \) | ההשוואה |
    |:-:|:-:|:-:|:-:|
    | ‏<span dir="ltr">9, 5</span> | 95 | 59 | ‏<span dir="ltr">95 > 59</span> |
    | ‏<span dir="ltr">5, 34</span> | 534 | 345 | ‏<span dir="ltr">534 > 345</span> |
    | ‏<span dir="ltr">34, 3</span> | 343 | 334 | ‏<span dir="ltr">343 > 334</span> |
    | ‏<span dir="ltr">3, 30</span> | 330 | 303 | ‏<span dir="ltr">330 > 303</span> |

    <!-- /gen -->

    שני דברים עוד לא ברורים : שהכלל הוא סדר שאפשר למיין לפיו (אם \( a \) לפני \( b \) ו-\( b \)
    לפני \( c \), האם \( a \) לפני \( c \)?), ושסדר בלי זוג שכנים "הפוך" הוא באמת המקסימום של כל
    \( n! \) הסדרים, ולא רק מקסימום מקומי. את שניהם מוכיחים בסעיף ב.

    #### סיבוכיות { .sol-cost }

    - **זמן :** ‏\( O(n \log n) \) השוואות, וכל אחת בונה שתי מחרוזות באורך עד \( 2L \) : סך הכול
      \( O(n \log n \cdot L) \). בקוד ה-SystemVerilog מיון ההכנסה הוא \( O(n^2 L) \), מספיק
      למודל ייחוס עם רשימה קצרה.
    - **זיכרון :** ‏\( O(n L) \) למחרוזות ולתוצאה.

### סעיף ב – למה זה נכון

??? tip "רמז 1"
    כתבו את \( a \Vert b \) כמספר : \( a \cdot 10^{|b|} + b \), כש-\( |b| \) מספר הספרות של \( b \).
    העבירו את כל מה שקשור ל-\( a \) לצד אחד של אי-השוויון.

??? tip "רמז 2"
    קחו סדר כלשהו שיש בו שני שכנים "הפוכים" לפי הכלל. מה קורה למספר כשמחליפים אותם? ומה זה אומר
    על סדר שהוא המקסימום?

??? success "פתרון סעיף ב"
    !!! answer "תשובה בקצרה"
        ‏\( a \Vert b \ge b \Vert a \) בדיוק כש-\( \frac{a}{10^{|a|} - 1} \ge \frac{b}{10^{|b|} - 1} \).
        לכל מחרוזת יש מספר אחד, \( 0.aaaa\ldots \), והכלל משווה את המספרים האלה, ולכן הוא
        טרנזיטיבי. שוויון, כמו 12 ו-1212 (שניהם \( 4/33 \)), נותן את אותה מחרוזת בשני הסדרים.
        ואם בסדר כלשהו יש שני שכנים הפוכים, ההחלפה שלהם מגדילה את המספר : לכן המקסימום ממוין, וכל
        הסדרים הממוינים נותנים אותה מחרוזת.

    <!-- cost: זמן \( O(n! \cdot n L) \) | זיכרון \( O(n L) \) -->

    #### הרעיון { .sol-idea }

    **מספר אחד לכל מחרוזת.** עם \( |a| \) מספר הספרות של \( a \) :

    \[
    \begin{aligned}
    a \Vert b \ge b \Vert a
    &\iff a \cdot 10^{|b|} + b \ge b \cdot 10^{|a|} + a \\
    &\iff a \left( 10^{|b|} - 1 \right) \ge b \left( 10^{|a|} - 1 \right) \\
    &\iff \frac{a}{10^{|a|} - 1} \ge \frac{b}{10^{|b|} - 1} .
    \end{aligned}
    \]

    הצד השמאלי של השורה האחרונה תלוי רק ב-\( a \), והימני רק ב-\( b \). נסמן
    \( \rho(a) = a / (10^{|a|} - 1) \). זה המספר שהספרות שלו אחרי הנקודה הן \( a \) שוב ושוב :
    \( \rho(34) = 34/99 = 0.3434\ldots \). הכלל "\( a \) לפני \( b \)" הוא בדיוק
    \( \rho(a) > \rho(b) \), ומיון לפי הכלל הוא מיון של מספרים ממשיים מהגדול לקטן. בדוגמה :

    <!-- gen 2 -->

    | המספר \( a \) | האורך | ‏\( a / (10^{\lvert a \rvert} - 1) \) | בצורה עשרונית | המקום בתשובה |
    |:-:|:-:|:-:|:-:|:-:|
    | 9 | 1 | ‏<span dir="ltr">9/9 = 1</span> | ‏<span dir="ltr">1</span> | 1 |
    | 5 | 1 | ‏<span dir="ltr">5/9</span> | ‏<span dir="ltr">0.555555…</span> | 2 |
    | 34 | 2 | ‏<span dir="ltr">34/99</span> | ‏<span dir="ltr">0.343434…</span> | 3 |
    | 3 | 1 | ‏<span dir="ltr">3/9 = 1/3</span> | ‏<span dir="ltr">0.333333…</span> | 4 |
    | 30 | 2 | ‏<span dir="ltr">30/99 = 10/33</span> | ‏<span dir="ltr">0.303030…</span> | 5 |

    <!-- /gen -->

    על הקטע מ-0 עד 1 : כל מספר הוא נקודה, והתשובה קוראת אותן מהגבוהה לנמוכה. 3 ו-30 קרובים,
    ‏<span dir="ltr">0.3333</span> מול <span dir="ltr">0.3030</span>, ולכן מיון של מחרוזות, שרואה
    רק ש-"30" ארוכה יותר, טועה דווקא בהם :

    #### הקוד { .sol-code }

    המשפט נבדק מול מודל ייחוס בכוח גס, שמנסה את כל הסדרים. בבדיקות של העמוד הוא רץ על אלפי
    רשימות קטנות מול `largest_number` :

    === "Python"
        ```python title="largest_brute" linenums="1" hl_lines="6"
        from itertools import permutations


        def largest_brute(nums: list[int]) -> str:
            """The largest concatenation by trying every order: a reference for small inputs."""
            best = max("".join(p) for p in permutations([str(x) for x in nums]))   # (1)!
            return "0" if best[0] == "0" else best
        ```

        1. כל הסדרים נותנים מחרוזות באותו אורך, ולכן `max` של מחרוזות הוא המקסימום של המספרים.

    === "SystemVerilog"
        ```systemverilog title="function largest_brute" linenums="1" hl_lines="6 11"
        // every order of s from position k on; the largest concatenation is kept in best
        function automatic void try_orders(ref string s[$], input int k, ref string best);
          string t, cand = "";
          if (k == s.size()) begin
            foreach (s[i]) cand = {cand, s[i]};
            if (best == "" || cand > best) best = cand;
            return;
          end
          for (int i = k; i < s.size(); i++) begin
            t = s[k]; s[k] = s[i]; s[i] = t;                 // (1)!
            try_orders(s, k + 1, best);
            t = s[k]; s[k] = s[i]; s[i] = t;
          end
        endfunction

        // the largest concatenation by trying every order: a reference for small inputs
        function automatic string largest_brute(int nums[]);
          string s[$], best = "";
          foreach (nums[i]) s.push_back($sformatf("%0d", nums[i]));
          try_orders(s, 0, best);
          return best[0] == "0" ? "0" : best;
        endfunction
        ```

        1. מביאים כל אחד מהנותרים למקום `k`, ממשיכים ברקורסיה, ומחזירים אותו למקומו.

    #### למה זה נכון { .sol-proof }

    **הכלל הוא סדר.** הוא משווה את \( \rho(a) \) ל-\( \rho(b) \), מספרים ממשיים, ולכן הוא
    טרנזיטיבי, וכל שני מספרים ניתנים להשוואה. שוויון \( \rho(a) = \rho(b) \) הוא יחס שקילות, ובו
    \( a \Vert b = b \Vert a \) : שני המספרים באותו אורך, ואף אחד מהם לא גדול מהשני. למשל
    ‏\( \rho(12) = 12/99 = 4/33 \) ו-\( \rho(1212) = 1212/9999 = 4/33 \), ושני הסדרים נותנים 121212.
    זה מה שמיון עם פונקציית השוואה צריך : סדר חלש מלא, ולא רק "איזה מהשניים גדול".

    **המיון נותן את המקסימום.** נניח שבסדר כלשהו יש שכנים \( u, v \) עם \( \rho(u) < \rho(v) \).
    מחליפים אותם : מה שלפניהם ומה שאחריהם לא זז, וגוש הספרות שלהם עולה מ-\( u \Vert v \) ל-\( v \Vert u \),
    שגדול ממנו ממש. לכן המספר כולו גדל ממש. יש מספר סופי של סדרים, אז יש סדר שנותן את המספר הגדול
    ביותר, ואין בו זוג כזה : ה-\( \rho \) שלו לא עולה לאורך כל השורה, כלומר הוא ממוין.

    **כל הסדרים הממוינים שווים.** שני סדרים ממוינים נבדלים רק בסדר שבתוך קבוצה של מספרים עם אותו
    \( \rho \), ושם כל שניים מתחלפים בלי לשנות את המחרוזת. לכן הסדר שהמיון החזיר נותן את אותה
    מחרוזת כמו הסדר הגדול ביותר.

    **אפסים.** ל-0 יש \( \rho(0) = 0 \), הקטן ביותר. אם התוצאה מתחילה ב-0, כל המספרים 0, ובמקום
    "00" מחזירים "0".

    #### סיבוכיות { .sol-cost }

    - **הכוח הגס :** ‏\( n! \) סדרים, וכל אחד \( O(n L) \) לבנות ולהשוות. ב-\( n = 8 \) זה
      40,320 סדרים, ומעבר לזה רק המיון.
    - **זיכרון :** ‏\( O(n L) \) : הרקורסיה מחליפה במקום, ונשמר רק הטוב ביותר.

    הספרה הראשונה שבה הוא נופל מ-9534330. בחרו את 3 ו-30 כזוג : <span dir="ltr">330 > 303</span>,

    #### הרעיון { .sol-idea }

    **בלי הדרישה זה סעיף ב הפוך.** אותה הוכחה, עם אי-השוויונות בכיוון השני, אומרת שמיון עולה
    לפי \( \rho \) נותן את הסדר הקטן ביותר. ל-0 יש \( \rho = 0 \), ולכן כל האפסים בהתחלה :
    ‏<span dir="ltr">[0, 1, 10]</span> נותן 0101. מחיקת האפסים נותנת 101, שזה כבר לא שרשור של כל
    המספרים : חסרה ספרה.

    #### השלבים { .sol-steps }

    <div class="steps" markdown>

    1. **מיון עולה :** \( a \) לפני \( b \) כש-\( a \Vert b < b \Vert a \). האפסים בהתחלה.
    2. **אפסים :** סופרים אותם, \( z \), ומוציאים אותם. אם לא נשאר כלום, מחזירים "0".
    3. **מועמדים :** לכל ערך \( x \) שאינו 0, פעם אחת לכל ערך : \( x \), אחריו \( z \) אפסים,
       ואחריהם השאר בסדר שלהם.
    4. **הבחירה :** המועמד הקטן ביותר. כל המועמדים באותו אורך, ולכן משווים מחרוזות.

    #### הקוד { .sol-code }

    === "Python"
        ```python title="smallest_number" linenums="1" hl_lines="3 13"
        def smallest_number(nums: list[int]) -> str:
            """The smallest number made by concatenating all of nums, with no leading zero."""
            s = sorted((str(x) for x in nums), key=cmp_to_key(lambda a, b: concat_order(b, a)))   # (1)!
            z = s.count("0")
            rest = s[z:]                                   # the non-zero strings, still in order
            if not rest:
                return "0"
            best, tried = None, set()
            for i, x in enumerate(rest):
                if x in tried:
                    continue
                tried.add(x)
                cand = x + "0" * z + "".join(rest[:i] + rest[i + 1:])   # (2)!
                if best is None or cand < best:            # (3)!
                    best = cand
            return best
        ```

        1. ‏`concat_order(b, a)` הוא הכלל של סעיף א בכיוון ההפוך : \( a \) קודם כש-\( a \Vert b < b \Vert a \).
           ‏"0" לפני כל מחרוזת אחרת, ולכן האפסים הם ה-`z` הראשונים.
        2. מחיקה של איבר מרשימה ממוינת משאירה אותה ממוינת : זה הסדר הטוב ביותר לשאר.
        3. כל המועמדים באותו אורך, ולכן `<` של מחרוזות הוא `<` של המספרים.

    === "SystemVerilog"
        ```systemverilog title="function smallest_number" linenums="1" hl_lines="7 15"
        // the smallest number made by concatenating all of nums, with no leading zero
        function automatic string smallest_number(int nums[]);
          string s[$], zeros = "", cand, best = "";
          bit tried[string];
          foreach (nums[i]) s.push_back($sformatf("%0d", nums[i]));
          sort_concat(s, 0);                                 // (1)!
          while (s.size() > 0 && s[0] == "0") begin
            zeros = {zeros, "0"};
            void'(s.pop_front());
          end
          if (s.size() == 0) return "0";
          foreach (s[i]) begin
            if (!tried.exists(s[i])) begin
              tried[s[i]] = 1;
              cand = {s[i], zeros};
              foreach (s[k]) if (k != i) cand = {cand, s[k]};
              if (best == "" || cand < best) best = cand;
            end
          end
          return best;
        endfunction
        ```

        1. אותו מיון הכנסה של סעיף א, בסדר עולה.

    #### למה זה נכון { .sol-proof }

    **אותו אורך.** כל סדר של אותם מספרים נותן מחרוזת באותו אורך, ולכן להשוות מספרים זה להשוות
    מחרוזות.

    **מה מותר.** מספר שלם נכתב בלי 0 מוביל, ולכן המחרוזת היחידה שמתחילה ב-0 היא "0". סדר מותר
    בדיוק כשהראשון בו אינו "0", או כשכל המספרים 0.

    **ראשון קבוע.** אחרי ש-\( x \) נבחר, שאר המספרים יכולים לבוא בכל סדר, ולפי סעיף ב בכיוון ההפוך
    הקטן ביותר מהם הוא המיון העולה. בו האפסים ראשונים : \( 0 \Vert a < a \Vert 0 \) לכל \( a \) שאינו
    0, כי \( a \) מתחיל בספרה שאינה 0. לכן הסדר המותר הקטן ביותר שמתחיל ב-\( x \) הוא בדיוק המועמד
    של \( x \).

    **הכול.** כל סדר מותר מתחיל באחד מהערכים שאינם 0, ולכן הוא לפחות המועמד של הערך הזה. הקטן
    מבין המועמדים הוא הקטן מבין כל הסדרים המותרים. בטבלה למעלה הוא שווה לכוח הגס בכל השורות, וכך
    גם בבדיקות של העמוד על אלפי רשימות.

    #### סיבוכיות { .sol-cost }

    - **זמן :** המיון \( O(n \log n \cdot L) \), ועוד \( k \) מועמדים של \( O(n L) \) כל אחד, כש-\( k \)
      מספר הערכים השונים שאינם 0. במקרה הגרוע \( O(n^2 L) \). כשאין אפסים, המועמד של הראשון
      במיון הוא כבר התשובה.
    - **זיכרון :** ‏\( O(n L) \).
    - **כלל עדין :** הכלל של הזוגות בוחר את כל הסדר, חוץ מהראשון. את הראשון צריך לבחור מול
      האפסים שאחריו, ואין לזה השוואה של זוג (ראו שאלות ההמשך).

    **נסו בעצמכם.** התיבה נפתחת על <span dir="ltr">[0, 2, 21]</span> במצב "הקטן ביותר". בשורות של

    "0, 1, 10" : שם ההזזה דווקא צודקת, 1001. לבסוף כתבו בשדה <span dir="ltr">0, 11, 1</span> : לפי
    הכלל 11 ו-1 שווים, המיון משאיר את 11 ראשון, וההזזה נותנת 1101 במקום 1011. התיבה מראה לכל רשימה

            ‏\( \rho(a) \) עצמו, מדויק : `Fraction(int(a), 10 ** len(a) - 1)`. בלי שברים : המחרוזת
            \( a \) שחוזרת על עצמה עד אורך \( 2L \). שתי סדרות מחזוריות שונות נבדלות כבר
            ב-\( |a| + |b| \) הספרות הראשונות (משפט Fine–Wilf), ולכן החיתוך לא משנה את הסדר.

    - **בודק בלי מודל ייחוס :** התכן מחזיר את הסדר שבחר. איך בודקים אותו ב-\( O(n L) \)?

        ??? fu-answer "תשובה"
            בודקים שזו תמורה של הקלט, ושכל זוג שכנים מקיים \( a \Vert b \ge b \Vert a \). לפי
            סעיף ב זה אומר ש-\( \rho \) לא עולה לאורך השורה, וכל סדר כזה נותן את המקסימום. אין
            צורך לחשב את התשובה בעצמנו.

    - **השוואה בחומרה :** איך נראית יחידה שמקבלת שני מספרים עם האורכים שלהם ומחליטה מי ראשון?

        ??? fu-answer "תשובה"
            לפי השורה השנייה של סעיף ב : \( a \cdot (10^{|b|} - 1) \) מול \( b \cdot (10^{|a|} - 1) \).
            טבלה קטנה של \( 10^k - 1 \), שני כופלים ומשווה אחד. רוחב המכפלה הוא סכום הרוחבים,
            בלי גלישה.

    - **הראשון בלי לנסות את כולם :** בסעיף ג, אפשר לבחור את הראשון ישר?

        ??? fu-answer "תשובה"
            הבדיקות של העמוד מאשרות על עשרות אלפי רשימות כלל אחד : הראשון הוא ה-\( x \) שהגוש
            \( x \) ואחריו \( z \) אפסים שלו הכי קטן לפי \( \rho \), וביניהם הארוך ביותר. לא
            הוכחנו אותו כאן. כלל ההזזה, וגם "הקטן ביותר בלי האפסים", נכשלים.
