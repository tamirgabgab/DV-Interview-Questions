## השאלה

כתבו פונקציה `swap` שמקבלת שני משתנים שלמים `a` ו-`b` (מסוג `int`) **by reference**
ומחליפה ביניהם: בסיום הריצה `a` מחזיק את הערך המקורי של `b`, ו-`b` מחזיק את הערך
המקורי של `a`.

השאלה מגיעה בשלושה סעיפים, וכל סעיף מוסיף אילוץ.

!!! info "הערה לגבי Python"
    ב-Python מספר שלם הוא אובייקט שאי אפשר לשנות (immutable), ולכן אין העברה של `int`
    by reference. המקבילה הקרובה היא להעביר רשימה `v` ושני אינדקסים `i`, `j`: הפונקציה
    משנה את `v[i]` ואת `v[j]` במקום, כך ש-`v[i]` משחק את התפקיד של `a` ו-`v[j]` את
    התפקיד של `b`.

??? interviewer "מה המראיין בודק"
    - **העברה by reference:** האם מבינים מה זה אומר שהפונקציה משנה את המשתנים של הקורא,
      ואיך עושים את זה בכל שפה.
    - **הוכחה ולא רק דוגמה:** בסעיפים ב ו-ג מצפים למעקב סימבולי אחרי \( a_0 \) ו-\( b_0 \),
      לא רק להרצה על 5 ו-3.
    - **מקרי קצה:** מה קורה כשהסכום חורג מהטווח של `int`, ומה קורה כששני הארגומנטים הם
      אותו משתנה.
    - **הבדלים בין שפות:** רוחב של `int`, חשבון מודולרי, ומה בכלל "משתנה עזר" ב-Python.

### סעיף א – עם משתנה עזר

כתבו את הפונקציה בצורה הפשוטה ביותר.

??? tip "רמז 1"
    ברגע שכותבים לתוך `a` הערך הישן שלו נעלם. מה צריך לעשות לפני ההשמה הראשונה?

??? success "פתרון סעיף א"
    !!! answer "תשובה בקצרה"
        משתנה עזר אחד ושלוש השמות: **`temp = a; a = b; b = temp`**.

    #### הרעיון { .sol-idea }

    שומרים את הערך של `a` במשתנה עזר `temp`, מעתיקים את `b` לתוך `a`, ולבסוף מעתיקים
    את `temp` לתוך `b`. בלי השמירה הראשונה, ההשמה `a = b` הייתה מוחקת את הערך המקורי של
    `a` ושני המשתנים היו מקבלים את `b`.

    #### השלבים { .sol-steps }

    <div class="steps" markdown>

    1. **לשמור:** `temp = a`, כדי שהערך המקורי של `a` לא יאבד.
    2. **לדרוס:** `a = b`, ועכשיו `a` כבר נכון.
    3. **לשחזר:** `b = temp`, הערך המקורי של `a`.

    </div>

    #### הקוד { .sol-code }

    === "SystemVerilog"
        ```systemverilog title="function swap_temp" hl_lines="3"
        function automatic void swap_temp(ref int a, ref int b);   // (1)!
          int temp;
          temp = a;   // (2)!
          a    = b;
          b    = temp;
        endfunction
        ```

        1. ב-SystemVerilog ארגומנט `ref` מחייב פונקציה `automatic`: הארגומנט הוא הפניה
           למשתנה של הקורא, ולכן השינוי בתוך הפונקציה נראה גם בחוץ. בלי `ref` הפונקציה
           הייתה מחליפה בין שני עותקים מקומיים ולא עושה כלום.
        2. השמירה חייבת לבוא לפני ההשמה `a = b`. זו הסיבה היחידה שצריך משתנה עזר.

    === "Python"
        ```python title="swap_temp" hl_lines="2"
        def swap_temp(v, i, j):
            temp = v[i]   # (1)!
            v[i] = v[j]
            v[j] = temp
        ```

        1. ‏`v[i]` משחק את התפקיד של `a`. הרשימה `v` היא אובייקט שאפשר לשנות, ולכן הכתיבה
           לתוכה נראית אצל הקורא, בניגוד להשמה למשתנה `int` מקומי.

        ב-Python הדרך המקובלת היא פשוט `v[i], v[j] = v[j], v[i]`.

    #### סיבוכיות { .sol-cost }

    ‏\( O(1) \) זמן: שלוש השמות. זיכרון נוסף: משתנה `int` אחד.

### סעיף ב – בלי משתנה עזר

כתבו את הפונקציה שוב, הפעם **בלי אף משתנה עזר**. מותר להשתמש בפעולות חשבון.
הוכיחו שהפונקציה אכן מחליפה בין הערכים.

??? tip "רמז 1"
    אסור לאבד מידע: אחרי הפעולה הראשונה עדיין צריך להיות אפשר לשחזר את **שני** הערכים
    המקוריים מתוך `a` ו-`b`. איזו פעולה חשבונית על שניהם שומרת את המידע הזה?

??? tip "רמז 2"
    אם `a` מחזיק את הסכום \( a + b \) ו-`b` עדיין מחזיק את הערך המקורי שלו, איך אפשר לשחזר
    את הערך המקורי של `a`?

??? success "פתרון סעיף ב"
    !!! answer "תשובה בקצרה"
        שומרים את הסכום ב-`a` ומחסירים ממנו פעמיים: **`a = a + b; b = a - b; a = a - b`**.
        זה נכון גם כשהסכום גולש, כי החשבון ב-`int` הוא מודולו \( 2^{32} \).

    #### הרעיון { .sol-idea }

    הסכום \( a_0 + b_0 \) מחזיק את שני הערכים ביחד: כל עוד אחד מהם עדיין זמין, חיסור
    מחזיר את השני. לכן שומרים את **הסכום** בתוך `a`, ואז "מחסירים החוצה" כל פעם את אחד
    הערכים.

    #### השלבים { .sol-steps }

    <div class="steps" markdown>

    1. **לחבר:** `a = a + b`, ועכשיו \( a = a_0 + b_0 \) בעוד \( b = b_0 \).
    2. **לשחזר את \( a_0 \) לתוך `b`:** `b = a - b`, כלומר \( (a_0 + b_0) - b_0 = a_0 \).
    3. **לשחזר את \( b_0 \) לתוך `a`:** `a = a - b`, כלומר \( (a_0 + b_0) - a_0 = b_0 \).

    </div>

    #### הקוד { .sol-code }

    === "SystemVerilog"
        ```systemverilog title="function swap_arith" hl_lines="2"
        function automatic void swap_arith(ref int a, ref int b);
          a = a + b;   // a = a0 + b0 (1)
          b = a - b;   // b = (a0 + b0) - b0 = a0 (2)
          a = a - b;   // a = (a0 + b0) - a0 = b0
        endfunction
        ```

        1. ‏`a` הוא "משתנה העזר" כאן: הסכום מכיל את שני הערכים המקוריים בבת אחת. הסכום
           יכול לגלוש, וזה לא מפריע (ראו "למה זה נכון").
        2. הסדר חשוב: `b` משוחזר קודם, כי בשלב הזה `b` עדיין מחזיק את \( b_0 \), ורק אותו
           אפשר להחסיר מהסכום.

    === "Python"
        ```python title="swap_arith" hl_lines="2"
        def swap_arith(v, i, j):
            v[i] = v[i] + v[j]   # a = a0 + b0 (1)
            v[j] = v[i] - v[j]   # b = (a0 + b0) - b0 = a0
            v[i] = v[i] - v[j]   # a = (a0 + b0) - a0 = b0
        ```

        1. אותו מבנה בדיוק, כש-`v[i]` הוא `a` ו-`v[j]` הוא `b`. ב-Python הסכום אף פעם לא
           גולש, כי מספרים שלמים הם בגודל לא מוגבל.

    #### למה זה נכון { .sol-proof }

    נסמן ב-\( a_0 \) וב-\( b_0 \) את הערכים ההתחלתיים, ונעקוב אחרי שני המשתנים אחרי כל שלב:

    | שלב | פעולה | ערך `a` | ערך `b` |
    |-----|-------|---------|---------|
    | התחלה | | ‏\( a_0 \) | ‏\( b_0 \) |
    | 1 | ‏`a = a + b` | ‏\( a_0 + b_0 \) | ‏\( b_0 \) |
    | 2 | ‏`b = a - b` | ‏\( a_0 + b_0 \) | ‏\( (a_0 + b_0) - b_0 = a_0 \) |
    | 3 | ‏`a = a - b` | ‏\( (a_0 + b_0) - a_0 = b_0 \) | ‏\( a_0 \) |

    בסוף \( a = b_0 \) ו-\( b = a_0 \), כלומר הערכים הוחלפו. \( \blacksquare \)

    **דוגמה מספרית** עם \( a = 5,\ b = 3 \): אחרי שלב 1 מתקבל \( a = 8 \), אחרי שלב 2
    מתקבל \( b = 8 - 3 = 5 \), ואחרי שלב 3 מתקבל \( a = 8 - 5 = 3 \).

    **ומה עם גלישה (overflow)?** הסכום \( a_0 + b_0 \) יכול לחרוג מהטווח של `int`, אבל
    השיטה עדיין עובדת. `int` ב-SystemVerilog הוא 32 ביט, והחשבון בו מתבצע **מודולו
    \( 2^{32} \)** (עטיפה של two's complement). כל השוויונים בטבלה נכונים גם בחשבון מודולרי:

    \[
    \big((a_0 + b_0) - b_0\big) \bmod 2^{32} = a_0 \bmod 2^{32}
    \]

    לכן גם אם הסכום "נעטף", ההחסרה מחזירה בדיוק את הערך הנכון. לדוגמה, עבור
    \( a = 2^{31} - 1 \) ו-\( b = 1 \): הסכום נעטף ל-\( -2^{31} \), ובכל זאת בסוף מתקבל
    \( a = 1 \) ו-\( b = 2^{31} - 1 \).

    ב-Python אין גלישה בכלל, כי מספרים שלמים הם בגודל לא מוגבל.

    #### סיבוכיות { .sol-cost }

    ‏\( O(1) \) זמן: שלוש פעולות חשבון. זיכרון נוסף: אפס, וזה כל העניין של הסעיף.

### סעיף ג – רק אופרטורים על ביטים

כתבו את הפונקציה בלי משתנה עזר **ובלי פעולות חשבון**: מותר להשתמש רק באופרטורים
בוליאניים שפועלים על ביטים (`&`, `|`, `^`, `~`). הוכיחו שגם כאן מתקבלת החלפה.

??? tip "רמז 1"
    חלק מהאופרטורים מאבדים מידע: אחרי `a = a & b` כבר אי אפשר לשחזר את `a` המקורי.
    איזה מהארבעה שומר מספיק מידע כדי לשחזר את שני הערכים, כמו שהסכום עשה בסעיף ב?

??? tip "רמז 2"
    איזה אופרטור מקיים \( x \oplus x = 0 \) ו-\( x \oplus 0 = x \)? הוא "מבטל את עצמו", בדיוק
    כמו חיבור וחיסור בסעיף ב.

??? success "פתרון סעיף ג"
    !!! answer "תשובה בקצרה"
        שלוש פעולות XOR באותו מבנה של סעיף ב: **`a = a ^ b; b = a ^ b; a = a ^ b`**.

    #### הרעיון { .sol-idea }

    ‏XOR משחק את התפקיד של חיבור **וגם** של חיסור: \( (x \oplus y) \oplus y = x \). לכן
    \( a_0 \oplus b_0 \) מחזיק את שני הערכים ביחד, ו-XOR נוסף עם אחד מהם מחזיר את השני,
    בדיוק כמו הסכום בסעיף ב, אבל בלי נשא (carry) ובלי גלישה.

    #### השלבים { .sol-steps }

    <div class="steps" markdown>

    1. **לשלב:** `a = a ^ b`, ועכשיו \( a = a_0 \oplus b_0 \) בעוד \( b = b_0 \).
    2. **לשחזר את \( a_0 \) לתוך `b`:** `b = a ^ b`, כלומר \( a_0 \oplus b_0 \oplus b_0 = a_0 \).
    3. **לשחזר את \( b_0 \) לתוך `a`:** `a = a ^ b`, כלומר \( a_0 \oplus b_0 \oplus a_0 = b_0 \).

    </div>

    #### הקוד { .sol-code }

    === "SystemVerilog"
        ```systemverilog title="function swap_xor" hl_lines="2"
        function automatic void swap_xor(ref int a, ref int b);
          a = a ^ b;   // a = a0 ^ b0 (1)
          b = a ^ b;   // b = a0 ^ b0 ^ b0 = a0 (2)
          a = a ^ b;   // a = a0 ^ b0 ^ a0 = b0
        endfunction
        ```

        1. אחרי השורה הזו `a` מחזיק את "ההפרש הביטי" בין שני הערכים: בכל מקום שבו הביטים
           היו שונים יש 1. ממנו ועוד אחד מהערכים המקוריים אפשר לשחזר את השני.
        2. אותן שלוש שורות בדיוק כמו בסעיף ב, כש-`^` מחליף גם את `+` וגם את `-`. אין כאן
           גלישה, כי XOR לא מייצר נשא בין ביטים.

    === "Python"
        ```python title="swap_xor" hl_lines="2"
        def swap_xor(v, i, j):
            v[i] = v[i] ^ v[j]   # a = a0 ^ b0 (1)
            v[j] = v[i] ^ v[j]   # b = a0 ^ b0 ^ b0 = a0
            v[i] = v[i] ^ v[j]   # a = a0 ^ b0 ^ a0 = b0
        ```

        1. ב-Python `^` על `int` פועל על ייצוג two's complement באורך לא מוגבל, ולכן
           הטריק עובד גם על מספרים שליליים.

    #### למה זה נכון { .sol-proof }

    **הוכחה אלגברית.** ההוכחה נשענת על ארבע תכונות של XOR (מסומן \( \oplus \)):

    | תכונה | נוסחה |
    |-------|-------|
    | ביטול עצמי | ‏\( x \oplus x = 0 \) |
    | איבר ניטרלי | ‏\( x \oplus 0 = x \) |
    | חילופיות | ‏\( x \oplus y = y \oplus x \) |
    | קיבוציות | ‏\( (x \oplus y) \oplus z = x \oplus (y \oplus z) \) |

    נעקוב אחרי השלבים:

    \[
    \begin{aligned}
    \text{1:}\quad a &= a_0 \oplus b_0 \\
    \text{2:}\quad b &= (a_0 \oplus b_0) \oplus b_0 = a_0 \oplus (b_0 \oplus b_0) \\
                     &= a_0 \oplus 0 = a_0 \\
    \text{3:}\quad a &= (a_0 \oplus b_0) \oplus a_0 = (a_0 \oplus a_0) \oplus b_0 \\
                     &= 0 \oplus b_0 = b_0
    \end{aligned}
    \]

    בסוף \( a = b_0 \) ו-\( b = a_0 \). \( \blacksquare \)

    **הוכחה בטבלת אמת.** XOR פועל על כל ביט בנפרד, בלי נשא (carry) בין ביטים. לכן מספיק
    להוכיח את הטענה לביט בודד, ואז היא נכונה לכל מספר, כולל מספרים שליליים. נבדוק את כל
    ארבעת הצירופים:

    | ‏\( a_0 \) | ‏\( b_0 \) | שלב 1: \( a = a_0 \oplus b_0 \) | שלב 2: \( b = a \oplus b_0 \) | שלב 3: \( a = a \oplus b \) |
    |:-:|:-:|:-:|:-:|:-:|
    | 0 | 0 | 0 | 0 = \( a_0 \) | 0 = \( b_0 \) |
    | 0 | 1 | 1 | 0 = \( a_0 \) | 1 = \( b_0 \) |
    | 1 | 0 | 1 | 1 = \( a_0 \) | 0 = \( b_0 \) |
    | 1 | 1 | 0 | 1 = \( a_0 \) | 1 = \( b_0 \) |

    **דוגמה מספרית** עם \( a = 5 = 0101_2 \) ו-\( b = 3 = 0011_2 \):

    | שלב | ‏`a` | ‏`b` |
    |-----|-----|-----|
    | התחלה | ‏`0101` (5) | ‏`0011` (3) |
    | 1: `a = a ^ b` | ‏`0110` (6) | ‏`0011` (3) |
    | 2: `b = a ^ b` | ‏`0110` (6) | ‏`0101` (5) |
    | 3: `a = a ^ b` | ‏`0011` (3) | ‏`0101` (5) |

    **לנסות בעצמכם.** התיבה הבאה מריצה את שלוש הגרסאות שורה אחרי שורה: בוחרים גרסה,
    מקלידים `a` ו-`b`, וליד כל ערך מופיע הביטוי הסימבולי ב-\( a_0 \) וב-\( b_0 \). המתג
    "אותו משתנה" מראה את המלכודת של `swap(v, i, i)`, והמתג של 8 ביט מראה את הגלישה של
    סעיף ב ולמה ההחלפה נכונה בכל זאת.

    <div class="explorer" data-kind="trace" data-mode="swap"></div>

    #### סיבוכיות { .sol-cost }

    ‏\( O(1) \) זמן: שלוש פעולות XOR, בלי זיכרון נוסף. שימו לב ששלוש הפעולות תלויות זו בזו
    (כל אחת משתמשת בתוצאה של הקודמת), ולכן הן מתבצעות בטור ולא במקביל.

## נקודות חשובות ושאלות המשך

??? trap "מלכודת: אותו משתנה פעמיים"
    אם קוראים לפונקציה עם **אותו משתנה** בשני הארגומנטים, למשל `swap(x, x)` או
    `swap(v, i, i)` ב-Python, שתי השיטות בלי משתנה עזר **מאפסות** את המשתנה:

    - **ב-XOR:** בשלב הראשון \( x = x \oplus x = 0 \), ומשם הערך נשאר 0.
    - **בחיבור וחיסור:** בשלב הראשון \( x = 2x \), ובשלב השני \( x = x - x = 0 \).

    הגרסה עם משתנה עזר לא נפגעת מזה. ב-Python אפשר להגן על הפונקציה עם בדיקה
    `if i == j: return`.

??? trap "מלכודת: גלישה בחיבור"
    כמו שהוסבר בסעיף ב, ב-SystemVerilog הגלישה לא מזיקה כי החשבון מודולרי, וב-Python אין
    גלישה. בשפות C ו-C++, לעומת זאת, גלישה של `int` עם סימן היא **התנהגות לא מוגדרת**
    (undefined behavior), ולכן שם צריך לעבוד עם טיפוס `unsigned`. שיטת ה-XOR לא סובלת
    מהבעיה הזו בשום שפה.

??? trap "מלכודת: לחשוב ש-XOR swap יותר מהיר"
    לא באמת. במעבדים מודרניים, ובקוד שעבר קומפילציה עם אופטימיזציה, הגרסה עם משתנה עזר
    בדרך כלל מהירה יותר: המשתנה נשמר ברגיסטר, ושלוש פעולות ה-XOR תלויות זו בזו ולכן
    מתבצעות בטור. השיטות של סעיפים ב ו-ג הן טריק שמראה הבנה של חשבון ושל ביטים, לא
    אופטימיזציה.

??? followup "שאלות המשך"
    - **סיבוב של שלושה משתנים:** איך מבצעים \( a \leftarrow b,\ b \leftarrow c,\ c \leftarrow a \)
      בלי משתנה עזר? כמה פעולות XOR צריך, ואיך זה קשור לכך שסיבוב של שלושה הוא שתי החלפות?
    - **טיפוסים אחרים:** האם הטריק של סעיף ב עובד על `real`? (חיבור של נקודה צפה לא מדויק,
      ולכן \( (a + b) - b \) לא תמיד שווה ל-\( a \).) ומה עם XOR על `real`?
    - **שאלת המשך מעולם החומרה, החלפה בין שני רגיסטרים:** ב-RTL אפשר להחליף בין שני
      רגיסטרים בלי משתנה עזר ובלי טריקים, בעזרת השמה לא-חוסמת (non-blocking):

        ```systemverilog
        always_ff @(posedge clk) begin
          a <= b;
          b <= a;
        end
        ```

        זה עובד כי בהשמה לא-חוסמת כל הביטויים בצד ימין נדגמים **לפני** שמתבצע עדכון כלשהו.
        בפועל זה שני Flip-Flops שכל אחד מקבל את המוצא של השני. אם היו כותבים כאן השמה חוסמת
        (`a = b; b = a;`), שני הרגיסטרים היו מקבלים את הערך של `b`.
