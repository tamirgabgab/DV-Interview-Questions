## השאלה

נתון מספר שלם `x` בין 0 ל-999. כותבים אותו **בדיוק עם 3 ספרות**, ומשלימים אפסים משמאל
לפי הצורך (למשל 7 נכתב 007, ו-45 נכתב 045). מהספרות האלה בונים שני מספרים :

- **מהגדול לקטן :** הספרות ממוינות בסדר יורד.
- **מהקטן לגדול :** הספרות ממוינות בסדר עולה.

מחסרים את הקטן מהגדול. אם ההפרש יוצא בדיוק `x`, המספר `x` נקרא **מיוחד**.

| המספר `x` | מהגדול לקטן | מהקטן לגדול | ההפרש | מיוחד? |
|---|---|---|---|---|
| 352 | 532 | 235 | 297 | ✗ |
| 7 | 700 | 007 | 693 | ✗ |
| 45 | 540 | 045 | 495 | ✗ |
| 111 | 111 | 111 | 0 | ✗ |
| 0 | 000 | 000 | 0 | ✓ |

??? interviewer "מה המראיין בודק"
    - **אפסים משלימים :** האם זוכרים ש-7 הוא 007. בלי זה מספרים קטנים מקבלים תוצאה שגויה.
    - **מיון של שלושה איברים :** אפשר בפונקציית מיון של השפה, אבל בשאלה על חומרה מצפים
      לרשת השוואות קבועה, בלי לולאה.
    - **להוכיח, לא רק להריץ :** הלולאה של סעיף ב נותנת את התשובה, אבל המראיין רוצה לשמוע
      למה היא נכונה.
    - **לצמצם את החיפוש :** האם באמת צריך לבדוק את כל 1,000 המספרים, או שההוכחה מצמצמת
      את המועמדים לקומץ?

### סעיף א – לבדוק מספר אחד

כתבו פונקציה שמקבלת את `x` ומחזירה 1 אם הוא מיוחד, ו-0 אחרת.

??? tip "רמז 1"
    איך מפרקים מספר לספרות בלי להמיר אותו למחרוזת? חלוקה ושארית ב-10.

??? tip "רמז 2"
    אחרי שהספרות ממוינות, שני המספרים נבנים מאותן שלוש ספרות : פעם בסדר אחד ופעם בסדר
    ההפוך. אין צורך למיין פעמיים.

??? success "פתרון סעיף א"
    !!! answer "תשובה בקצרה"
        מפרקים לשלוש ספרות (האפסים המשלימים מתקבלים לבד), ממיינים אותן, בונים מהן את
        הגדול ואת הקטן, ומחזירים 1 אם ההפרש שווה ל-`x`.

    #### הרעיון { .sol-idea }

    שני המספרים בנויים מאותן שלוש ספרות, ולכן מספיק למיין פעם אחת : המספר הגדול הוא
    הספרות בסדר יורד, והקטן הוא אותן ספרות בסדר הפוך.

    #### השלבים { .sol-steps }

    <div class="steps" markdown>

    1. **לפרק :** הספרות הן `x / 100`, `(x / 10) % 10` ו-`x % 10`. האפסים המשלימים
       מתקבלים לבד : עבור 7 יוצא 0, 0, 7.
    2. **למיין :** את שלוש הספרות בסדר יורד, \( a \ge b \ge c \).
    3. **להרכיב :** הגדול הוא \( 100a + 10b + c \) והקטן הוא \( 100c + 10b + a \).
    4. **להשוות :** את ההפרש ל-`x`.

    </div>

    #### הקוד { .sol-code }

    === "SystemVerilog"
        ```systemverilog title="function is_special" hl_lines="6 7 8"
        function automatic bit is_special(int x);
          int a = x / 100, b = (x / 10) % 10, c = x % 10;   // leading zeros come for free (1)
          int largest, smallest;

          // Sort the three digits in descending order: a >= b >= c
          if (a < b) {a, b} = {b, a};   // (2)!
          if (b < c) {b, c} = {c, b};   // (3)!
          if (a < b) {a, b} = {b, a};   // (4)!

          largest  = 100 * a + 10 * b + c;
          smallest = 100 * c + 10 * b + a;   // (5)!
          return largest - smallest == x;
        endfunction
        ```

        1. חלוקה שלמה ושארית מפרקות את `x` לספרות. עבור `x = 7` מתקבל `a = 0`, `b = 0`,
           `c = 7`, בדיוק כמו 007. לא צריך טיפול מיוחד במספרים קטנים.
        2. השוואה־והחלפה ראשונה : אחריה `a >= b`. ההחלפה `{a, b} = {b, a}` היא השמה
           לשרשור, ולכן לא צריך משתנה עזר.
        3. אחרי ההשוואה הזו הספרה הקטנה ביותר מבין השלוש נמצאת ב-`c`.
        4. ההחלפה הראשונה יכלה להתקלקל בשלב 3 (אם `b` קיבל ערך גדול יותר), ולכן מסדרים
           שוב את `a` ו-`b`. שלוש ההשוואות האלה הן רשת מיון (sorting network) לשלושה
           איברים.
        5. אותן ספרות בסדר הפוך. הספרה האמצעית `b` נשארת במקומה בשני המספרים.

        בחומרה שלוש ההשוואות הן מעגל צירופי של שלושה משווים, בלי לולאה.

    === "Python"
        ```python title="is_special"
        def is_special(x: int) -> int:
            digits = sorted(f"{x:03d}")              # three digits, leading zeros included (1)
            smallest = int("".join(digits))           # ascending order
            largest = int("".join(reversed(digits)))  # descending order (2)
            return int(largest - smallest == x)
        ```

        1. ‏`f"{x:03d}"` מרפדת באפסים משמאל לשלוש ספרות, ו-`sorted` על המחרוזת מחזירה
           רשימה של תווים בסדר עולה. מיון של ספרות כתווים זהה למיון שלהן כמספרים, כי כולן
           באותו אורך.
        2. ‏`reversed` הופכת את הסדר העולה ליורד, בלי מיון שני.

    #### סיבוכיות { .sol-cost }

    ‏\( O(1) \) : תמיד שלוש ספרות, שלוש השוואות ושני מספרים להרכיב.

### סעיף ב – לבדוק את כל המספרים

מריצים את הפונקציה על כל המספרים מ-0 עד 999, ושומרים במערך את אלה שהיא מחזירה עבורם 1.
מה יכיל המערך בסוף? הוכיחו.

??? tip "רמז 1"
    כתבו את ההפרש בעזרת הספרות הממוינות \( a \ge b \ge c \). מה קורה לספרת האמצע?

??? tip "רמז 2"
    ההפרש הוא תמיד כפולה של מספר קבוע. כמה כפולות כאלה יש בין 0 ל-999? מספיק לבדוק רק
    אותן.

??? success "פתרון סעיף ב"
    !!! answer "תשובה בקצרה"
        המערך יכיל שני מספרים בלבד : **0 ו-495**.

    #### הרעיון { .sol-idea }

    ספרת האמצע מתבטלת בחיסור, ולכן ההפרש הוא תמיד \( 99(a - c) \) : אחת מעשר כפולות של
    99. מספר מיוחד חייב להיות אחת מהן, ובדיקה של עשרת המועמדים משאירה רק את 0 ואת 495.

    #### הקוד { .sol-code }

    === "SystemVerilog"
        ```systemverilog title="function find_special"
        function automatic void find_special(ref int special[$]);
          special.delete();   // (1)!
          for (int x = 0; x <= 999; x++)
            if (is_special(x)) special.push_back(x);
        endfunction
        ```

        1. התור מגיע מהקורא (`ref`), ולכן מרוקנים אותו קודם : אחרת קריאה שנייה הייתה
           מוסיפה את התוצאות פעם נוספת.

    === "Python"
        ```python title="find_special"
        def find_special() -> list[int]:
            return [x for x in range(1000) if is_special(x)]
        ```

    #### למה זה נכון { .sol-proof }

    <div class="steps" markdown>

    1. **ההפרש תמיד כפולה של 99.** נסמן את הספרות הממוינות \( a \ge b \ge c \). אז :

        \[
        \begin{aligned}
        & (100a + 10b + c) - (100c + 10b + a) \\
        & \quad = 99a - 99c = 99(a - c)
        \end{aligned}
        \]

        ספרת האמצע \( b \) מתבטלת. נסמן \( k = a - c \), ולכן \( 0 \le k \le 9 \).

    2. **המקרה \( k = 0 \).** כל הספרות שוות וההפרש הוא 0. המספר היחיד מהצורה הזו
       שההפרש שלו שווה לו הוא 0 עצמו. למשל 111 נותן הפרש 0, ולא 111.

    3. **הספרות של \( 99k \).** כש-\( 1 \le k \le 9 \), ההפרש הוא

        \[
        99k = 100(k - 1) + 10 \cdot 9 + (10 - k)
        \]

        ולכן הספרות שלו הן \( k - 1 \), ‏9 ו-\( 10 - k \), כולל אפס משלים (עבור \( k = 1 \)
        יוצא 099).

    4. **התנאי ש-`x` שווה להפרש.** אם \( x = 99k \), הספרות של `x` הן אותן ספרות
       \( a, b, c \). הספרה 9 נמצאת ביניהן, והיא הספרה הגדולה ביותר האפשרית, ולכן
       \( a = 9 \) ו-\( c = a - k = 9 - k \). מוציאים את ה-9 משני הצדדים :

        \[
        \{\, b,\; 9 - k \,\} = \{\, k - 1,\; 10 - k \,\}
        \]

        הספרה \( 9 - k \) חייבת להיות אחת משתי הספרות מימין :

        - **‏\( 9 - k = 10 - k \) :** בלתי אפשרי.
        - **‏\( 9 - k = k - 1 \) :** כלומר \( k = 5 \). אז \( b = 10 - k = 5 \), והמספר הוא
          \( x = 99 \cdot 5 = 495 \).

    5. **בדיקה.** הספרות של 495 ממוינות הן 9, 5, 4, ו-\( 954 - 459 = 495 \). ∎

    </div>

    **כל המועמדים בטבלה אחת.** לפי שלב 1, רק עשרה מספרים יכולים להיות מיוחדים :
    \( 0, 99, 198, \ldots, 891 \). הנה תשעת המועמדים שאינם 0 :

    | ‏\( k \) | המספר \( 99k \) | מהגדול לקטן | מהקטן לגדול | ההפרש | מיוחד? |
    |---|---|---|---|---|---|
    | 1 | 099 | 990 | 099 | 891 | ✗ |
    | 2 | 198 | 981 | 189 | 792 | ✗ |
    | 3 | 297 | 972 | 279 | 693 | ✗ |
    | 4 | 396 | 963 | 369 | 594 | ✗ |
    | 5 | 495 | 954 | 459 | **495** | ✓ |
    | 6 | 594 | 954 | 459 | 495 | ✗ |
    | 7 | 693 | 963 | 369 | 594 | ✗ |
    | 8 | 792 | 972 | 279 | 693 | ✗ |
    | 9 | 891 | 981 | 189 | 792 | ✗ |

    שימו לב שהשורות של \( k \) ו-\( 10 - k \) מכילות את אותן ספרות, ולכן נותנות את אותו
    הפרש. רק ב-\( k = 5 \) השורה מתאימה לעצמה.

    **נסו בעצמכם.** הקלידו מספר או הגרילו אחד : הטבלה מראה את המיון ואת החיסור, ואז
    מפעילים את אותו צעד על ההפרש שוב ושוב. חוץ ממספרים שכל הספרות שלהם שוות (שנופלים ל-0),
    כולם מגיעים ל-495 ונעצרים שם, וההיסטוגרמה מראה אחרי כמה צעדים.

    <div class="explorer" data-kind="kaprekar" data-digits="3"></div>

    #### סיבוכיות { .sol-cost }

    הלולאה בודקת 1,000 מספרים, כל אחד ב-\( O(1) \). לפי ההוכחה אפשר לבדוק רק את עשר
    הכפולות של 99, אבל בראיון הלולאה המלאה היא התשובה המצופה לקוד, וההוכחה היא התשובה
    המצופה לשאלה "מה יכיל המערך".

## נקודות חשובות ושאלות המשך

??? trap "מלכודת : אפסים משלימים"
    הפתרון הנפוץ ביותר שנכשל הוא מיון של הספרות **בלי** לרפד באפסים. אז 45 הופך ל-"54"
    ו-"45", ההפרש הוא 9 במקום 495, וגם ההוכחה של סעיף ב משתנה. מספר בן פחות משלוש
    ספרות הוא עדיין מספר בן שלוש ספרות בשאלה הזו.

??? followup "שאלות המשך"
    - **לחזור על התהליך :** מתחילים ממספר שלא כל הספרות שלו שוות, ומפעילים שוב ושוב את
      "ממיינים ומחסרים" על התוצאה. תמיד מגיעים ל-495, ולכל היותר אחרי 6 צעדים. למשל
      \( 352 \to 297 \to 693 \to 594 \to 495 \).
    - **ארבע ספרות :** המספרים המיוחדים הם 0 ו-6174 (הקבוע של Kaprekar), ומכל מספר שלא כל
      הספרות שלו שוות מגיעים ל-6174 תוך 7 צעדים לכל היותר. זו שאלה 0013.
    - **שתי ספרות :** רק 0 מיוחד. כל מספר אחר נכנס למעגל
      \( 09 \to 81 \to 63 \to 27 \to 45 \to 09 \).
    - **בחומרה :** כתבו מודול צירופי שמקבל 3 ספרות BCD ומוציא את ההפרש. כמה משווים
      וכמה מחסרים צריך?
