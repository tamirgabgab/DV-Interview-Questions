## השאלה

‏LFSR (Linear Feedback Shift Register) של 4 ביטים מזיז את המצב ימינה בכל מחזור : הביט
הנמוך `s[0]` יוצא החוצה, וביט חדש נכנס למקום העליון. הביט החדש הוא XOR של כמה ביטים של
המצב, ה-**taps**. את ה-taps נהוג לרשום כפולינום : \( x^4 + x^3 + 1 \) פירושו XOR של הביט
שיוצא (‏\( x^4 \), כלומר `s[0]`) עם הביט שמעליו (‏\( x^3 \), כלומר `s[1]`); באופן כללי
\( x^k \) הוא הביט `s[4 - k]`.

??? interviewer "מה המראיין בודק"
    - **מכניקה :** האם המועמד יודע לסמלץ LFSR ביד ובקוד בלי להתבלבל בכיוון ההזזה ובאיזה
      ביט ה-tap יושב.
    - **מצב האפס :** למה `0000` נתקע, ולכן המקסימום הוא \( 2^n - 1 \) ולא \( 2^n \).
    - **אינטואיציה אלגברית :** לא נדרשת תורת שדות, אבל כן ההבנה שהמחזור תלוי בפולינום
      ושפולינום שמתפרק נותן מחזור קצר.
    - **שימוש :** איפה משתמשים ב-LFSR באימות (מחוללי מספרים פסאודו-אקראיים, CRC,
      BIST, scramblers) ומה חשוב לבדוק בו.

### סעיף א – שני רצפים

התחילו מהמצב `0001` וכתבו את רצף המצבים עבור \( x^4 + x^3 + 1 \) ועבור \( x^4 + x^2 + 1 \).
אחרי כמה צעדים כל אחד מהם חוזר למצב ההתחלה? כתבו פונקציה שמחשבת צעד אחד ופונקציה
שמחשבת את אורך המחזור.

??? tip "רמז 1"
    בכל צעד : חשבו את ביט ההיזון החוזר מה-taps של המצב **הנוכחי**, הזיזו את המצב ימינה
    ביט אחד, והכניסו את ההיזון החוזר למקום העליון. עקבו עם טבלה.

??? tip "רמז 2"
    אורך המחזור הוא מספר הצעדים עד שהמצב חוזר על עצמו. שמרו את המצבים שראיתם; המצב
    הראשון שחוזר סוגר מחזור.

??? success "פתרון סעיף א"
    !!! answer "תשובה בקצרה"
        עם \( x^4 + x^3 + 1 \) (‏taps `0011`) הרצף מ-`0001` עובר דרך כל 15 המצבים שאינם
        אפס וחוזר ל-`0001` אחרי **15** צעדים. עם \( x^4 + x^2 + 1 \) (‏taps `0101`) הרצף
        חוזר ל-`0001` כבר אחרי **6** צעדים.

    <!-- cost: פלופים \( n \) | זמן \( O(2^n) \) -->

    #### הרעיון { .sol-idea }

    הצעד הוא דטרמיניסטי : המצב הבא נקבע רק מהמצב הנוכחי. לכן, מרגע שמצב חוזר על עצמו,
    כל הרצף חוזר. מסמלצים צעד אחר צעד ושומרים את המצבים שכבר ראינו; מספר הצעדים עד
    החזרה הראשונה הוא אורך המחזור.

    #### השלבים { .sol-steps }

    <div class="steps" markdown>

    1. **ה-taps כמסכה :** \( x^k \) הוא `s[4 - k]`, ולכן \( x^4 + x^3 + 1 \) הוא המסכה
       `0011` (ביטים 0 ו-1) ו-\( x^4 + x^2 + 1 \) הוא `0101` (ביטים 0 ו-2). האיבר \( 1 \)
       בפולינום מייצג את הביט שנכנס, לא ביט של המצב. זו צורת **Fibonacci** של ה-LFSR,
       והפולינום כתוב כאן לפי חיבורי ההיזון החוזר; ספר שכותב את הפולינום האופייני של
       הרצף מקבל את אותם taps במראה (המלכודת על הכיוון, בסוף הדף).
    2. **צעד :** `fb = parity(state & mask)`, ואז `state = (state >> 1) | (fb << 3)`.
    3. **מחזור :** מריצים מ-`0001` עד שהמצב הראשון חוזר.

    </div>

    #### הקוד { .sol-code }

    === "Python"
        ```python title="lfsr_next, lfsr_period" hl_lines="2 3 11"
        def lfsr_next(state: int, mask: int, width: int) -> int:
            fb = bin(state & mask).count("1") & 1          # (1)!
            return (state >> 1) | (fb << (width - 1))      # (2)!


        def lfsr_period(mask: int, width: int, seed: int = 1) -> int:
            """Steps from `seed` until a state repeats: the length of the cycle reached."""
            seen, s, k = {}, seed, 0
            while s not in seen:
                seen[s] = k
                s = lfsr_next(s, mask, width)
                k += 1
            return k - seen[s]                             # (3)!
        ```

        1. הזוגיות של הביטים שה-taps בוחרים.
        2. הזזה ימינה, והביט החדש נכנס למקום העליון.
        3. ההפרש בין הצעד הנוכחי לצעד שבו המצב נראה לראשונה הוא אורך המחזור.

    === "SystemVerilog"
        ```systemverilog title="function lfsr_next, lfsr_period" hl_lines="2 3 12"
        function automatic int lfsr_next(int state, int mask, int width);
          bit fb = ^(state & mask);                       // (1)!
          return (state >> 1) | (int'(fb) << (width - 1));   // (2)!
        endfunction

        // Steps from `seed` until a state repeats; the length of the cycle reached
        function automatic int lfsr_period(int mask, int width, int seed = 1);
          int seen[int];                                  // (3)!
          int s = seed, k = 0;
          while (!seen.exists(s)) begin
            seen[s] = k;
            s = lfsr_next(s, mask, width);
            k++;
          end
          return k - seen[s];
        endfunction
        ```

        1. ‏`^` על מספר הוא ה-XOR של כל הביטים שלו : הזוגיות של הביטים שה-taps בוחרים.
        2. הזזה ימינה, והביט החדש נכנס למקום העליון. הביט שיצא, `state[0]`, הוא המוצא של
           ה-LFSR.
        3. מערך אסוציאטיבי : מצב → באיזה צעד ראינו אותו. ההפרש בין הצעד הנוכחי לצעד
           שבו המצב נראה לראשונה הוא אורך המחזור (זנב לפני המחזור, אם יש, לא נספר).

    ומכל מצב התחלה, ומציירת את כל המחזורים של הפולינום, טבעת לכל מחזור.

    - נסו : לחצו על \( x^4 + x^2 + 1 \) ועל "עד שהמצב חוזר". המחזור נסגר אחרי 6 צעדים,
      ותשעה מצבים נשארים לבנים; שלוש הטבעות הן <span dir="ltr">6 + 6 + 3</span>.
    - נסו : באותו פולינום לחצו בציור על המצב `0110`. המחזור שלו הוא 3 צעדים בלבד. לחצו

    - נסו : סמנו את כל ה-taps, \( x^4 + x^3 + x^2 + x + 1 \). שלוש טבעות של 5 : פולינום
      אי-פריק שאינו פרימיטיבי.

      <span dir="ltr">100011110101100</span> מול <span dir="ltr">100010011010111</span>.
    - נסו : עברו ל-5 ביטים. כמה שורות בטבלה מסומנות ב-✓? שש, כמו

    #### סיבוכיות { .sol-cost }

    חומרה : \( n \) פלופים ושערי XOR כמספר ה-taps פחות אחד, בלי מונים ובלי השוואות; זו
    הסיבה ש-LFSR הוא מהמחוללים הפסאודו-אקראיים הזולים ביותר. חישוב המחזור בתוכנה :
    \( O(2^n) \) צעדים במקרה הגרוע, עם טבלה בגודל המחזור.

### סעיף ב – למה 15 הוא המקסימום, ולמה לא כל פולינום מגיע אליו

הסבירו למה אורך המחזור של LFSR עם \( n \) ביטים הוא לכל היותר \( 2^n - 1 \), למה
\( x^4 + x^3 + 1 \) מגיע ל-15 ו-\( x^4 + x^2 + 1 \) לא, ומצאו את כל הפולינומים מהצורה
\( x^4 + \ldots + 1 \) שנותנים מחזור מקסימלי.

??? tip "רמז 1"
    כמה מצבים שונים יש ל-4 ביטים? מה קורה ל-LFSR שמגיע ל-`0000`?

??? tip "רמז 2"
    נסו לחלק את \( x^4 + x^2 + 1 \) בפולינום ממעלה 2, כשהמקדמים מחושבים מודולו 2. מה
    המחזור של LFSR של 2 ביטים עם הגורם שמצאתם?

??? success "פתרון סעיף ב"
    !!! answer "תשובה בקצרה"
        המצב `0000` הוא נקודת שבת (XOR של אפסים הוא אפס), ולכן מחזור שלא כולל אותו עובר
        לכל היותר דרך \( 2^n - 1 = 15 \) מצבים. מחזור מקסימלי מתקבל בדיוק כשהפולינום
        **פרימיטיבי** : אי-פריק, ומסדר \( 2^n - 1 \). ‏\( x^4 + x^3 + 1 \) ו-\( x^4 + x + 1 \)
        פרימיטיביים (15); ‏\( x^4 + x^2 + 1 = (x^2 + x + 1)^2 \) מתפרק, והמחזור שלו הוא 6;
        \( x^4 + x^3 + x^2 + x + 1 \) אי-פריק אבל לא פרימיטיבי (הוא מחלק את \( x^5 - 1 \))
        ונותן 5.

    <!-- cost: צעדים \( 2^{n-1} \cdot 2^n \) -->

    #### הרעיון { .sol-idea }

    צעד של LFSR הוא העתקה ליניארית על וקטורים של \( n \) ביטים, והפולינום מקודד אותה.
    אורך המחזור מהמצב `0001` הוא הסדר של \( x \) מודולו הפולינום : המספר הקטן ביותר
    \( m \) שעבורו \( x^m \equiv 1 \). יש שלושה מקרים. כשהפולינום **פרימיטיבי** הסדר הוא
    \( 2^n - 1 \) ועוברים דרך כל המצבים. כשהוא **אי-פריק ולא פרימיטיבי** הסדר מחלק את
    \( 2^n - 1 \) וקטן ממנו. כשהוא **מתפרק**, הסדר הוא הכפולה המשותפת הקטנה ביותר של
    הסדרים של הגורמים השונים, וגורם שחוזר פעמיים מכפיל אותה ב-2 (ובאופן כללי, גורם
    שחוזר מכפיל בחזקה של 2).

    #### השלבים { .sol-steps }

    <div class="steps" markdown>

    1. **החסם :** יש \( 2^4 = 16 \) מצבים, ו-`0000` נשאר במקומו. אף מצב אחר לא מגיע
       אליו, כי הצעד הפיך : `s[0]`, האיבר \( x^n \), הוא תמיד tap, ולכן מהמצב הבא אפשר
       לשחזר את הביט שיצא. לכן המחזור מהמצב `0001` כולל לכל היותר 15 מצבים.
    2. **הפירוק של \( x^4 + x^2 + 1 \) :** \( (x^2 + x + 1)^2 = x^4 + 2x^3 + 3x^2 + 2x + 1 \),
       ומודולו 2 זה \( x^4 + x^2 + 1 \). הסדר של \( x \) מודולו \( x^2 + x + 1 \) הוא 3,
       כי \( x^3 - 1 = (x - 1)(x^2 + x + 1) \). מודולו הריבוע הסדר הוא 6 : \( x^3 - 1 \)
       מכיל את הגורם פעם אחת בלבד, ו-\( x^6 - 1 = (x^3 - 1)^2 \) (מודולו 2) מכיל אותו
       פעמיים. מכיוון ש-\( x^6 \equiv 1 \), כל מצב חוזר לעצמו אחרי 6 צעדים ואף מחזור אינו
       ארוך מ-6 (הקשר בין צעד לכפל ב-\( x \) מוסבר ב"למה זה נכון").
    3. **למה \( x^4 + x^3 + 1 \) מקסימלי :** הוא אי-פריק (אין לו שורש ב-\( \{0, 1\} \) ואינו
       מתחלק ב-\( x^2 + x + 1 \), הפולינום האי-פריק היחיד ממעלה 2). 15 השאריות שאינן
       אפס מודולו פולינום אי-פריק ממעלה 4 הן חבורה כפלית, ולכן הסדר של \( x \) מחלק את
       \( 15 \). הסדר אינו 1, 3 או 5 (בדיקה ישירה : \( x^3 \ne 1 \),
       ‏\( x^5 = x^3 + x + 1 \ne 1 \) מודולו הפולינום), ולכן הוא 15.
    4. **כל הפולינומים :** מתוך שמונה הפולינומים \( x^4 + \ldots + 1 \) בדיוק שניים
       פרימיטיביים, \( x^4 + x^3 + 1 \) ו-\( x^4 + x + 1 \) (ההפכי שלו : אותם מקדמים בסדר
       הפוך, ולכן אותו רצף ביטים במוצא, בסדר זמן הפוך). באופן כללי יש \( \varphi(2^n - 1) / n \) פולינומים
       פרימיטיביים ממעלה \( n \) : כאן \( \varphi(15) / 4 = 8 / 4 = 2 \).

    </div>

    #### למה זה נכון { .sol-proof }

    **הטבלה.** כל פולינום \( x^4 + \ldots + 1 \), המסכה שלו ואורך המחזור מ-`0001`,
    מהפונקציה של סעיף א :

    <!-- gen 2 -->

    | הפולינום | ביטי ה-taps (‏`s[3:0]`) | אורך המחזור מ-`0001` | מקסימלי? |
    |:-:|:-:|:-:|:-:|
    | ‏\( x^4 + 1 \) | ‏`0001` | ‏4 |  |
    | ‏\( x^4 + x^3 + 1 \) | ‏`0011` | ‏15 | ✓ |
    | ‏\( x^4 + x^2 + 1 \) | ‏`0101` | ‏6 |  |
    | ‏\( x^4 + x + 1 \) | ‏`1001` | ‏15 | ✓ |
    | ‏\( x^4 + x^3 + x^2 + 1 \) | ‏`0111` | ‏7 |  |
    | ‏\( x^4 + x^3 + x + 1 \) | ‏`1011` | ‏6 |  |
    | ‏\( x^4 + x^2 + x + 1 \) | ‏`1101` | ‏7 |  |
    | ‏\( x^4 + x^3 + x^2 + x + 1 \) | ‏`1111` | ‏5 |  |

    <!-- /gen -->

    **ולמה הסדר של \( x \) הוא אורך המחזור.** ביט המוצא מקיים נוסחת נסיגה ליניארית :
    ב-\( x^4 + x^3 + 1 \) זו \( a_{t+4} = a_t + a_{t+1} \) מודולו 2. הצעד הוא העתקה
    ליניארית על המצב, והפולינום האופייני שלה הוא \( P \) (ליתר דיוק ההפכי של \( P \), שיש
    לו אותו סדר). בבסיס מתאים ההעתקה היא כפל ב-\( x \) מודולו הפולינום הזה : אחרי
    \( m \) צעדים המצב \( S \) הוא \( x^m S \), והוא חוזר להיות \( S \) לראשונה
    כש-\( x^m \equiv 1 \) (כש-\( S \) זר לפולינום, תמיד כאשר הוא אי-פריק). מצב ההתחלה
    `0001` נותן את הסדר המלא; למצבים אחרים המחזור מחלק אותו, ובפולינום פריק הוא יכול
    להיות קצר יותר (ב-\( x^4 + x^2 + 1 \) המצב `0110` חוזר אחרי 3 צעדים). את כל המחזורים
    של כל פולינום רואים בתיבה של סעיף א.

    #### סיבוכיות { .sol-cost }

    בדיקה ישירה של הפולינומים : \( 2^{n-1} \) פולינומים כפול \( 2^n \) צעדים, זניח ל-\( n \)
    קטן. ל-\( n \) גדול (32, 64) לא מסמלצים : בודקים אי-פריקות ואת הסדר אלגברית, או
    לוקחים taps מטבלאות מוכנות.

## נקודות חשובות ושאלות המשך

??? trap "מלכודת : לאתחל את ה-LFSR לאפס"
    מ-`0000` ה-LFSR לא יוצא לעולם (סעיף ב). לכן ה-reset של LFSR הוא תמיד ערך שאינו אפס
    (לרוב כל אחדות), ובטסטבנץ' כדאי assertion שהמצב לעולם אינו אפס (`a_nonzero` בשאלת
    ההמשך על החומרה). גרסה עם XNOR הופכת את הבעיה : שם המצב התקוע הוא כל אחדות, כשמספר
    ה-taps זוגי, כמו בכל פולינום מקסימלי.

??? trap "מלכודת : taps בכיוון הלא נכון"
    אותו פולינום ממומש אחרת כשמזיזים שמאלה במקום ימינה, או כשמספרים את הביטים
    מהצד השני. \( x^4 + x^3 + 1 \) ו-\( x^4 + x + 1 \) הם זוג הפכי : אם בחרתם את המסכה לפי
    הקונבנציה ההפוכה תקבלו את הרצף של הפולינום השני. שניהם מקסימליים, ולכן הטעות לא
    תתגלה באורך המחזור, רק כשמשווים לרצף ייחוס (למשל של scrambler בתקן). גם ספרים
    חלוקים : יש שכותבים את פולינום חיבורי ההיזון, כמו כאן, ויש שכותבים את הפולינום
    האופייני של הרצף, שהוא ההפכי שלו.

??? trap "מלכודת : פולינום אי-פריק אינו בהכרח פרימיטיבי"
    ‏\( x^4 + x^3 + x^2 + x + 1 \) אי-פריק, אבל המחזור שלו הוא 5 ולא 15 : הוא מחלק את
    \( x^5 - 1 \). לכן "אין לו גורמים" לא מספיק, וצריך לבדוק שהמחזור הוא בדיוק
    \( 2^n - 1 \), כמו בטבלה של סעיף ב.

??? trap "מלכודת : להשוות Fibonacci מול Galois"
    ל-LFSR בצורת Fibonacci (XOR של כמה ביטים אל הכניסה) ולצורת Galois (XOR בתוך השרשרת)
    עם אותו פולינום יש אותו מחזור, אבל רצף המצבים שונה; ביטי המוצא זהים עד הזזת פאזה.
    מי שמשווה את המצבים של מימוש Galois לטבלת המצבים של Fibonacci יחשוב שיש באג.

??? followup "שאלות המשך"
    - **חומרה ואימות :** כתבו את ה-LFSR כמודול, וכתבו checker שמוודא שהמחזור הוא בדיוק
      \( 2^n - 1 \). מה עוד כדאי לבדוק?

        ??? fu-answer "תשובה"
            ה-LFSR הוא \( n \) פלופים ו-XOR אחד על ה-taps; ה-reset טוען seed שאינו אפס.

            ```systemverilog title="module lfsr" linenums="1" hl_lines="11"
            // Fibonacci LFSR: shift right, s[0] out, the XOR of the taps in at the top
            module lfsr #(
              parameter int W = 4,
              parameter logic [W-1:0] TAPS = 4'b0011,   // x^4 + x^3 + 1: s[0] and s[1]
              parameter logic [W-1:0] SEED = 4'b0001    // any value but zero
            ) (
              input  logic clk, rst_n,
              output logic [W-1:0] state,
              output logic out
            );
              always_ff @(posedge clk or negedge rst_n)
                if (!rst_n) state <= SEED;
                else        state <= {^(state & TAPS), state[W-1:1]};
              assign out = state[0];
            endmodule
            ```

            ה-checker מחזיק שלוש assertions ו-coverpoint עם bin לכל מצב שאינו אפס :

            ```systemverilog title="module lfsr_sva" linenums="1" hl_lines="7 8 9"
            // bound to lfsr: never zero, back at the seed after exactly 2^W - 1 clocks
            module lfsr_sva #(parameter int W = 4, parameter logic [W-1:0] SEED = 4'b0001) (
              input logic clk, rst_n, input logic [W-1:0] state
            );
              localparam int P = 2**W - 1;
              int fails = 0;
              a_nonzero: assert property (@(posedge clk) disable iff (!rst_n) state != '0) else fails++;
              a_period:  assert property (@(posedge clk) disable iff (!rst_n) state == SEED |-> ##P state == SEED) else fails++;
              a_first:   assert property (@(posedge clk) disable iff (!rst_n) state == SEED |=> (state != SEED)[*P-1]) else fails++;   // (1)!

              covergroup cg @(posedge clk);
                cp_state: coverpoint state iff (rst_n) { bins s[] = {[1:P]}; }   // (2)!
              endgroup
              cg cov = new();
            endmodule
            ```

            1. ‏`a_period` לבדה לא מספיקה : עם \( x^4 + x^3 + x^2 + x + 1 \) המחזור הוא 5, ו-15
               הוא כפולה של 5, ולכן המצב חוזר ל-seed גם אחרי 15 מחזורי שעון. `a_first` דורשת
               שהוא לא יחזור קודם.
            2. פולינום פרימיטיבי ממלא את כל 15 ה-bins. עם \( x^4 + x^2 + 1 \) מתמלאים רק 6,
               כלומר 40% כיסוי.

            עוד שתי בדיקות : השוואה של ביטי המוצא לרצף ייחוס, כי שני כיווני ה-taps עוברים את
            כל ה-assertions ואת הכיסוי ונותנים רצפים שונים; ומה קורה כשהמצב נופל ל-`0000`
            (הפרעה, או seed שגוי) : `a_nonzero` נופלת, ותכן שיש בו לוגיקת התאוששות צריך
            לצאת משם.

    - **‏LFSR של 8 ביטים :** כמה פולינומים פרימיטיביים יש? מצאו אחד בסימולציה.

        ??? fu-answer "תשובה"
            יש \( \varphi(255) / 8 = 128 / 8 = 16 \). אחד מהם \( x^8 + x^6 + x^5 + x^4 + 1 \),
            כלומר taps `0x1D` במוסכמה של הדף, ו-`lfsr_period(0x1D, 8)` מחזיר 255.

    - **‏Galois LFSR :** אותו פולינום, אבל ה-XOR-ים יושבים בין הפלופים במקום על ההיזון
      החוזר. למה זה מהיר יותר בחומרה, ומה הקשר בין שני הרצפים?

        ??? fu-answer "תשובה"
            ב-Galois כל XOR יושב בין שני פלופים, ולכן במסלול הקריטי יש XOR אחד בלי קשר למספר
            ה-taps, במקום עץ XOR על ההיזון החוזר. המחזור זהה, וביט המוצא הוא אותו רצף מקסימלי
            בהזזת פאזה (לפעמים עם הפולינום ההפוך, לפי המוסכמה); המצבים עצמם שונים.

    - **‏CRC :** ה-LFSR עם קלט הוא בדיוק חישוב שארית מודולו הפולינום. מה קורה ל-CRC-8
      \( x^8 + x^2 + x + 1 \) כשהפולינום אינו פרימיטיבי, ולמה זה בסדר ל-CRC אבל לא
      למחולל מספרים?

        ??? fu-answer "תשובה"
            הפולינום מתפרק : \( (x + 1)(x^7 + x^6 + x^5 + x^4 + x^3 + x^2 + 1) \), והמחזור 127
            (או 1 מ-`0xFF`). ל-CRC זה טוב : \( x + 1 \) תופס כל מספר אי-זוגי של שגיאות, והגורם
            השני כל זוג שגיאות במרחק קטן מ-127. למחולל מספרים מחזור קצר ומצבים חסרים הם החיסרון.

    - **‏scrambler של PCIe :** הפולינום \( x^{16} + x^5 + x^4 + x^3 + 1 \) עם seed `0xFFFF`.
      כמה סמלים עד שהרצף חוזר, ואיך בודקים את זה בלי לסמלץ 65,535 צעדים?

        ??? fu-answer "תשובה"
            המחזור הוא 65,535 : הפולינום פרימיטיבי, ולכן כל מצב שאינו אפס, גם `0xFFFF`, נמצא על
            מחזור אחד באורך \( 2^{16} - 1 \). בודקים בלי סימולציה : \( x^{65535} \equiv 1 \pmod{p} \),
            ו-\( x^{65535/q} \not\equiv 1 \) לכל \( q \in \{3, 5, 17, 257\} \), בכמה עשרות העלאות בריבוע.
