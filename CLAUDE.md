# CLAUDE.md — working rules for this repository

This is a Hebrew, right-to-left MkDocs Material site of Design Verification interview
questions, published to GitHub Pages from `main`. `README.md` has the links to the site;
`CONTRIBUTING.md` documents the content format and the tooling; `CATALOG.md` lists the
questions (written by `tools/catalog.py`); `HANDOFF.md` is the living task list and work
log. Read `CONTRIBUTING.md` and `HANDOFF.md` before a work session, and update
`HANDOFF.md` (work log, open items) at the end of every session.

## Language and RTL

- Always answer the owner in Hebrew, never in English: every chat reply, status update,
  question and end-of-round summary, also after a model switch or a context summary.
  English appears only as relevant technical terms, identifiers and file names inside a
  Hebrew sentence. Question content is Hebrew. Code, comments, identifiers,
  commit messages, `README.md`, `CONTRIBUTING.md`, `HANDOFF.md` and this file are English.
- Times shown to the owner are Israel time (Asia/Jerusalem: UTC+3 in summer time, UTC+2
  in winter; summer time ends on 25 October 2026), never UTC. Tools report UTC: convert
  before writing, e.g. "23:31 (שעון ישראל)".
- RTL safety: every paragraph, heading, list item and table cell starts with a Hebrew word.
  A line that must start with Latin text, inline code, a number followed by a period, or
  math gets the RLM mark (U+200F, `‏`) first. English terms go in the middle or at the end
  of a sentence.
- Colons in Hebrew text have a space on both sides: a non-breaking space (U+00A0) before,
  so the colon never wraps to the start of a line, and an ordinary space after ("סיבוב 8 :
  שלום", "**זמן :** ..."). This covers pages, admonition titles, figure generators, the
  explorer strings (`docs/javascripts/explorer/`) and the hook's HTML. It does not apply
  to times and ratios (12:00, 23:58:59), code, math, URLs or English-only text.
- No Hebrew inside MathJax (`\text{...}` renders reversed). In inline SVG, Hebrew `<text>`
  gets `direction="rtl"`; prefer an HTML legend over SVG text.
- No math in headings: the sidebar's table of contents and the search
  results show headings as plain text, so `\( L - 1 \)` appears raw there. Write the
  heading in words ("L − 1", "בזיכרון קבוע") and keep its old anchor with `{ #id }`.
- Long display math or inline chains widen the page on phones: split equations with
  `aligned`, write number chains as text in `<span dir="ltr">`.

## Question pages

- One Markdown file per question: `docs/questions/<level>/<id>-<slug>.md`, zero-padded id
  unique across the repository, `level` equal to the folder. Start from
  `templates/question.md`; the skeleton (interviewer block, hint ladder, short answer,
  solution blocks idea → steps → code → proof → cost, traps, follow-ups) is described in
  `CONTRIBUTING.md` and enforced by `python tools/lint_pages.py`.
- Code answers in SystemVerilog and Python as linked tabs, SystemVerilog first. The pages
  are the single source of truth: tests and the run panel execute the page code as is, so
  never change code on a page without running its tests. Annotation markers (`// (1)!`,
  `# (1)!`, or ` (1)` at the end of a comment) are the only decoration allowed on code
  lines.
- Figures are inline SVG generated by `tools/figures/q<id>.py`; the page copy must match
  the generator output (tests check it). New generators define `blocks()`, use
  `tools/figures/charts.py`, and their blocks sit between `<!-- gen n -->` markers that
  `python tools/figures/fill.py <id>` rewrites. Colours come from CSS variables in
  `docs/stylesheets/extra.css`, never hard-coded.
- Start a question with `python tools/new_question.py` (see `CONTRIBUTING.md`). Interactive
  sliders are a `data-kind` with its own file in `docs/javascripts/explorer/` (the shared
  code is `core.js`), tested under Node.
- The owner's own code is kept as sent; comments may be added, and bugs are called out to
  the owner rather than silently fixed.
- A source file from the owner (a solution write-up with tables and formulas) is checked
  first: recompute every table, example and closed form in the question's test with exact
  arithmetic, try the edge cases of the general formula, and tell the owner what does not
  hold before writing the page (0026–0028 found a capped last person and one rounding).

## Tests and checks

```bash
python tools/lint_pages.py            # page skeleton and RTL rules
python tools/run_tests.py             # pytest + Verilator (needs Verilator 5.052+ with z3)
mkdocs build --strict                 # the build CI runs
python tools/check_links.py           # internal links and anchors of the built site
python tools/check_phone.py           # every page at 390 px (add --offline and --route in a sandbox)
python tools/check_explorers.py       # every explorer box: buttons clicked, link and saved state
python tools/check_contrast.py        # the site's colour pairs, light and dark (WCAG 2)
```

The linter checks RTL at every paragraph start (indented blocks and the steps timeline
included) and warns about literal SVG colours; the phone check also warns about display
math wider than its column (split it with `aligned`) and about figure text under 9 px at
390 px. `--scheme dark` runs the phone check
in dark mode; CI runs it only on a manual run with `phone_dark`. Node runs the explorer
tests (`docs/javascripts/*.js` against the Python reference).

All seven run in CI on every push that touches the site (a push of only README, CONTRIBUTING,
CATALOG, HANDOFF or this file runs nothing, and `main` skips the checks for a commit that
already passed on its branch); a failure blocks the deploy. A new colour pair (a text
or a mark on a fill) goes into the `PAIRS` list of `tools/check_contrast.py`. Verilator
notes and simulator quirks are listed in `HANDOFF.md` under "Technical notes".

## Workflow

- Ask the owner guiding questions before a big change, then implement; end a work round
  with a short summary by sections.
- Develop on the designated work branch. Push to `main` (which publishes the site) only
  when the owner asks. Fast-forward `main` to the branch; do not rewrite history.
- Commit messages: English, imperative, with a short body for anything non-obvious. No
  model identifiers in commits, code or docs.
- Check the live result after a deploy: desktop and phone width (390 px), light and dark
  mode. Local screenshot checks need the CDN scripts routed to local copies (see
  `HANDOFF.md`).
